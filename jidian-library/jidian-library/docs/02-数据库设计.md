# 02 · 数据库设计

> 对应《实际编码规范》第八、九节，共 **9 张表**。本文件是小程序端字段口径的依据：
> 页面上出现的每个字段都必须能在下面的表里找到来源。

---

## 1. 建库

```sql
CREATE DATABASE IF NOT EXISTS library_seat
DEFAULT CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

USE library_seat;
```

## 2. 九张表

### 2.1 user —— 学生用户

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    openid VARCHAR(64) NOT NULL UNIQUE,
    nickname VARCHAR(64),
    avatar_url VARCHAR(255),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP
);
```

小程序端只有 `nickname` 与 `avatar_url` 可编辑，`id` / `openid` / `created_at` / `updated_at` 只读。

### 2.2 admin_user —— 管理员

```sql
CREATE TABLE admin_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP
);
```

密码必须 BCrypt，明文不得写进代码。只有一条管理员记录，不做角色与权限树。

### 2.3 seat —— 座位

```sql
CREATE TABLE seat (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    seat_code VARCHAR(50) NOT NULL UNIQUE,
    area VARCHAR(50),
    floor INT,
    device_id VARCHAR(64) NOT NULL UNIQUE,
    status TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP
);
```

`status` 取值 0~4，与 `utils/config.js` 的 `seatStatus` 一一对应：

| 值 | 枚举 | 含义 |
| --- | --- | --- |
| 0 | FREE | 空闲 |
| 1 | RESERVED | 已预约 |
| 2 | USING | 使用中 |
| 3 | AWAY | 暂离 |
| 4 | ALARM | 异常告警 |

> 离线不是 `seat.status`，由 `seat_shadow.online` 表达。

### 2.4 reservation —— 预约 / 使用记录

```sql
CREATE TABLE reservation (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    seat_id BIGINT NOT NULL,
    status VARCHAR(20) NOT NULL,
    reserve_time DATETIME NOT NULL,
    sign_time DATETIME NULL,
    leave_time DATETIME NULL,
    return_time DATETIME NULL,
    release_time DATETIME NULL,
    reserve_expire_at DATETIME NULL,
    leave_expire_at DATETIME NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_reservation_user_status(user_id, status),
    INDEX idx_reservation_seat_status(seat_id, status),
    INDEX idx_reservation_reserve_expire(reserve_expire_at),
    INDEX idx_reservation_leave_expire(leave_expire_at)
);
```

`status` 取值：`RESERVED` / `USING` / `AWAY` / `COMPLETED` / `CANCELLED` / `TIMEOUT`。

> 注意：创建预约**只入参 `seat_id`**，没有时段字段，因此表中也没有 start / end。

### 2.5 rfid_user —— 校园卡绑定

```sql
CREATE TABLE rfid_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    rfid_uid VARCHAR(64) NOT NULL UNIQUE,
    user_id BIGINT NOT NULL UNIQUE,
    bind_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

一对一绑定。小程序端只读，绑定 / 解绑走管理端：

```
GET    /api/admin/rfid-binds
POST   /api/admin/rfid-binds
DELETE /api/admin/rfid-binds/{uid}
```

### 2.6 seat_shadow —— 设备最新状态（设备影子）

```sql
CREATE TABLE seat_shadow (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    seat_id BIGINT NOT NULL UNIQUE,
    device_id VARCHAR(64) NOT NULL UNIQUE,
    pressure_adc INT NOT NULL DEFAULT 0,
    pir_state TINYINT NOT NULL DEFAULT 0,
    alarm_flag TINYINT NOT NULL DEFAULT 0,
    online TINYINT NOT NULL DEFAULT 0,
    last_report_at DATETIME NULL,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP
);
```

只保存「现在设备是什么状态」，**不保存 rfid_uid，不保存历史数据**。
历史进入 `study_record` 与 `violation`。

### 2.7 study_record —— 学习记录

```sql
CREATE TABLE study_record (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    seat_id BIGINT NOT NULL,
    reservation_id BIGINT NOT NULL UNIQUE,
    start_time DATETIME NOT NULL,
    end_time DATETIME NULL,
    duration_minutes INT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

时长算法（规范第四十三节，最简方案）：

```
start_time       = reservation.sign_time
end_time         = reservation.release_time
duration_minutes = TIMESTAMPDIFF(MINUTE, start_time, end_time)
```

暂离期间不拆成多段，整个使用周期算一段。

### 2.8 violation —— 违规 / 异常

```sql
CREATE TABLE violation (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NULL,
    seat_id BIGINT NOT NULL,
    type VARCHAR(30) NOT NULL,
    description VARCHAR(255),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_violation_seat(seat_id),
    INDEX idx_violation_user(user_id),
    INDEX idx_violation_created(created_at)
);
```

只保留三类 `type`，不增加积分、信用分、黑名单等级：

| type | 含义 | 产生方 |
| --- | --- | --- |
| `FAKE_OCCUPY` | 假占座 | 设备端双传感器融合 |
| `RESERVATION_TIMEOUT` | 预约超时未签到 | 云端定时任务 |
| `AWAY_TIMEOUT` | 暂离超时未回座 | 云端定时任务 |

### 2.9 operation_log —— 管理员操作日志

```sql
CREATE TABLE operation_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    admin_id BIGINT NOT NULL,
    operation VARCHAR(50) NOT NULL,
    target VARCHAR(100),
    description VARCHAR(255),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_operation_log_created(created_at)
);
```

记录：强制释放、消除告警、修改 ADC 阈值、测试蜂鸣器、RFID 绑定、RFID 解绑。

## 4. 前端拿到的字段口径

后端出参一律是 VO，经 Jackson 的 `SNAKE_CASE` 策略序列化，
所以**线上传输的字段名与数据库列名一致**。小程序侧由 `utils/api.js` 的
`normUser()` / `normSeat()` / `normReservation()` 消费。

```js
// 登录 POST /api/auth/wechat-login
// WechatLoginVO = UserVO 拍平 + token，一次请求拿全，不用再发一次「我的资料」
{ token,
  user_id, openid, nickname, avatar_url,
  created_at, updated_at, rfid_uid, rfid_bind_time }

// 座位 GET /api/seats（SeatVO）
{ seat_id, seat_code, area, floor, status, alarm, online,
  student_name, reserve_time, sign_time }

// 预约（ReservationVO，三个预约接口共用同一个 VO）
{ id, seat_id, seat_code, area, floor, seat_no, status,
  reserve_time, sign_time, leave_time, return_time, release_time,
  reserve_expire_at, leave_expire_at }
```

三个刻意的取舍：

- **`student_name` 只在管理端接口里返回。** 学生侧的 `/api/seats` 走的是
  `listSeats()`，不查预约人姓名 —— 谁坐在哪个座位不该让所有人看到。
  管理端走 `listSeatsForAdmin()`，才有这个字段。
- **原始传感器值不发给小程序。** `pressure_adc` / `pir_state` / `last_report_at`
  只出现在 `SeatDetailVO` 和 `DeviceVO` 里，即 `/api/admin/seats/{id}` 和
  `/api/admin/devices`。小程序只看合成后的 `status`，见 `03-OneNET接入与物模型设计.md` §7。
- **预约 VO 的主键叫 `id`，不叫 `reservation_id`。** 小程序三个预约接口
  都过同一个 `normReservation()`，它读的是 `id`；改名会让取消/离座/回座
  打到 `/api/reservations/0/cancel` 上。

命名统一规则（规范第四节）：

- 数据库 snake_case：`seat_code` / `reserve_expire_at` / `last_report_at`
- Java camelCase：`seatCode` / `reserveExpireAt` / `lastReportAt`
- JSON 与数据库一致，也用 snake_case
- 不出现 `seatID` / `SeatCode` 这类第三种写法

> ⚠️ `SNAKE_CASE` **管不到 `@RequestParam` 的参数名**。查询参数必须显式写
> `@RequestParam(name = "seat_id")`，漏了就变成 `seatId`，前端传的值收不到。

## 5. 配置参数

不放数据库，统一写在 `application.yml`（小程序端对应 `utils/config.js` 的 `business`）：

| 参数 | 值 | 用途 |
| --- | --- | --- |
| 预约超时 | 15 分钟 | RESERVED → TIMEOUT → FREE |
| 暂离超时 | 30 分钟 | AWAY → COMPLETED → FREE |
| 设备离线判定 | 120 秒 | 设备 60 秒一次心跳，允许丢一次包 |
| 单次学习时长上限 | 720 分钟 | 防止异常数据拉爆统计 |
