## 1. 五条不能破的红线

规范和数据分层是为了**答辩时能讲清楚**，也是为了让接口改动不牵连页面。
下面五条都有自动校验脚本兜底（§7），但脚本只查得到形式，查不到动机。

### 1.1 网络出口只有两个文件

| 允许 | 禁止 |
| --- | --- |
| `utils/request.js` 出现 `wx.request` | 页面、`api.js`、`util.js` 里出现 `wx.request` |
| `utils/ws.js` 出现 `wx.connectSocket` | 页面里自己调 `wx.connectSocket` / `wx.sendSocketMessage` |

页面统一通过 `utils/api.js` 取数，`api.js` 通过 `request.js` 取数。
页面代码里**不出现任何接口路径与字段名** —— 后端改了字段命名风格，
只需要动 `api.js` 的归一化层，9 个页面一行都不用改。

### 1.2 不造数据：没有后端就没有数据

- 工程里**没有也不该有** `staticData.js` / `onenet.js` / `thingModel.js`；
- `config.business` 里**不许有编造的值**。原来有个 `serviceTel: '022-2665-1234'`，
  是随手编的电话（还接到了 `wx.makePhoneCall`），已经删掉；反馈页的"电话反馈"卡片也一样；
- **意见反馈页是有意做成静态表单的**，不发请求。文案必须如实说明，
  不能再写"已收到你的反馈 / 1 个工作日内处理"这类空承诺；
- `utils/api.js` 的 `normUser()` 里，后端没给的字段一律留空，不补默认值。

### 1.3 `console` 只有一个出口

全项目**唯一**允许出现 `console` 的地方是 `utils/ws.js` 里的 `debugLog()`，
由 `config.debug.log` 控制，**交付版是 `false`**（一行都不往控制台打）。

联调 WebSocket 连不上、消息解析失败时，把 `config.js` 里 `debug.log` 改成 `true` 即可，
不需要删注释再改回来。目前 `ws.js` 里有 5 处 `debugLog`。

### 1.4 不自己推导状态

前端**不根据 `pressure_adc` / `pir_state` 推断「有人无人」**。
设备原始值只给 Web 管理端看（排查用），小程序只接受后端合成好的三个字段：

| 字段 | 小程序端怎么用 |
| --- | --- |
| `status` 0~4 | **座位图配色、可预约判断的唯一依据**；`4` 才红闪 |
| `alarm` | 冗余布尔，方便列表直接画角标 |
| `online` | 叠加「离线」角标，**不覆盖**业务状态 |

三条容易写错的细节：

1. **`alarm_flag` 不由任何前端判断。** 设备上报的 `alarm_flag` 由后端合成进
   `seat.status`、翻成 `4` 才发出去；前端看到 `status === 4` 就红闪。
2. **离线不是座位状态。** 座位状态只有 0~4 五个值，离线是 `online` 这个附加布尔。
   一个离线、但上次是"使用中"的座位，仍然显示「使用中 + 离线角标」，
   **不能显示成空闲**（这是最容易顺手写错的一处）。
3. **`online` 缺失时按在线处理**（`normSeat()` 就是这么写的），
   避免后端某个接口漏带这个字段时满屏"离线"。

### 1.5 状态枚举不许自创

- 座位状态**只用 0~4**，与 `seat.status` 的 TINYINT 一一对应；
- 预约状态**只用 6 个字符串**：`RESERVED / USING / AWAY / COMPLETED / CANCELLED / TIMEOUT`；
- 文案与配色统一从 `config.seatStatus` / `config.reservationStatus` 取，
  禁止在页面里散落颜色值和中文状态名 —— 新增状态时只改 `config.js` 一处。

另外 `utils/util.js` **只导出页面真正用到的 12 个方法**。
`hashCode` / `seededRandom`（已删假数据层的种子函数）、`distance`（已删"设备/附近"功能的遗物）
是**明确不要再加回来**的；`pad` / `formatDate` / `today` / `monthDayOf` 是内部函数，**不导出**
（避免再出现"导出了但没人用"的假接口）。

## 2. 后端地址只改一处

`utils/config.js` 的 `server.baseUrl` 是小程序里**唯一**的地址来源：

- HTTP：`request.js` 读它拼 URL；
- WebSocket：`ws.js` 用 `base.replace(/^http/, 'ws')` 推导，`https → wss`、`http → ws` 全自动。

所以**别去别处找地址**。自查脚本里有一条「后端地址只写在 `utils/config.js`」的断言守这个不变量。

### 2.1 穿透域名变了，要跟着改的第二处（最容易漏）

cpolar 免费版域名约 24 小时轮换、客户端重启就变。域名一变：

| # | 要改的地方 | 说明 |
| --- | --- | --- |
| 1 | 小程序 `utils/config.js` 的 `server.baseUrl` | **唯一的代码改动点** |
| 2 | **OneNET 控制台 → 产品开发 → 数据推送 → HTTP 全局推送** 的 url | 形如 `https://<域名>/api/onenet/device-data?push_secret=<密钥>`。**最容易被漏掉的一处** —— OneNET 在云上、**访问不到 localhost**，不改这里设备上报与刷卡签到就全断。同一页还要确认：消息加密方式=明文、**生效状态开关已打开** |
| 3 | 不用改的（别乱找） | 后端（Spring 只监听 8080，CORS 与 WS 都已 `allowedOriginPatterns("*")`，它不需要知道自己的公网地址）；`library-admin/vite.config.js` 的 `BACKEND`（那是给 vite 代理到**本机** 8080 用的）；手机端（不用填任何地址） |

> 想让别人从外网开管理端，得**另开一条 cpolar 隧道指向 3000**，与小程序那条互相独立。

## 3. 微信平台侧的坑

### 3.1 微信登录已经不用了（2026-09-30 起）

学生端改成**学号 + 密码自助注册**（`POST /api/auth/register` / `login`），密码在后端 BCrypt 校验。
全链路里**没有任何一步会访问微信服务器**，所以原本一堆「微信侧」的麻烦事整体消失了：

- ❌ 不再需要 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`；
- ❌ 不再需要公众平台的 **IP 白名单** —— 那个白名单只管「后端带 AppSecret 去调微信接口」这一件事；
- ❌ 不再受"微信拿不到昵称头像"的影响 —— 昵称现在由用户注册时自己填（选填）。

> ✅ **仍然存在**的是「合法域名」那一套：小程序请求自己的后端照样要过微信的域名校验，见 §3.3。
> 这两件事经常被混为一谈（一个是微信服务端校验**后端出口 IP**，一个是客户端校验**请求域名**），注意区分。

> 登录 / 注册页的隐私协议文案必须与代码的**实际行为**一致：
> 要写明「采集学号与密码，密码用于登录校验，不会下发回客户端」；
> ⚠️ 但**不能**再写「不保存明文」—— 库里另有一列明文 `password_plain`（见 01-数据库设计）。
> 「我的」页提供昵称输入并 `PUT /api/users/me` 保存，所以不能写「不采集昵称」；
> 头像自 2026-10-08 起统一使用固定的默认图片（`images/default_avatar.png`），
> 页面不提供上传，`avatar_url` 列保留但不写入 —— 协议里可以明确写「不采集头像」。
>
> **为什么不做头像上传**：`wx.chooseAvatar` 返回的是**设备本地临时路径**（`wxfile://...`），
> 只在本次运行内有效，重启小程序或换设备后必然加载不出来；要真正可用就得先用
> `wx.uploadFile` 把文件传到服务器再存 URL，而后端既没有文件上传接口也没有静态资源映射。
> 与其在库里存一个重启就失效的假地址，不如统一显示默认图 —— 功能边界清楚，答辩也好解释。

### 3.2 学生登录 401 的含义变了

改成学号密码之后，`/api/auth/login` 返回 401 **只有两个原因**：
学号没注册过，或者密码打错了。两者返回的提示**一字不差**（防学号枚举），所以别去猜是哪种。

排查顺序：

1. 数据库里到底有没有这个账号：`SELECT id, student_no, nickname FROM \`user\`;`
2. 密码确实忘了 → 目前**没有做自助改密**，只能重置：
   `UPDATE \`user\` SET password = '<新的BCrypt哈希>' WHERE student_no = '...';`
   生成哈希：项目里跑一次 `System.out.println(new BCryptPasswordEncoder().encode("新密码"));` 打印出来即可。

> 历史遗留：改造前用的是 `POST /api/auth/wechat-login`（`wx.login` 换 `openid`），
> 那时 401 的真因确实在后端日志里（`errcode=40164`：出口 IP 不在白名单）。
> 那段代码已经删掉，相关排查经验对本项目不再适用。

### 3.3 合法域名是两个入口，不是一个

微信公众平台「服务器域名」里有**两个独立输入框**：

- **request 合法域名** → REST 接口；
- **socket 合法域名** → WebSocket。

这是最容易出现"看着都对但不工作"的地方：只配了 request 的话，
REST 全通、页面数据也正常，**但座位不会自动刷新** —— 握手被微信直接拦掉，
只有在控制台才能看到一句 `connectSocket` 报错。带上线的清单里别漏第二个输入框。

小程序**不支持用 IP、不支持自签名证书**，两个输入框都只收 HTTPS + 已备案域名。

### 3.4 cpolar 域名配不进白名单，真机只能走"开发调试"

实测结论：`*.cpolar.top` 不是已备案域名，**request / socket 两个输入框都配不进去**。
所以真机联调必须绕过校验，而且**两步都要做**：

1. 开发者工具「详情 → 本地设置」勾选
   「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」；
2. **手机上再开一次**：打开小程序 → 右上角「···」→ 开发调试 → 打开。

**只做第 1 步，真机会报 `url not in domain list`。**

另外优先用 `https` / `wss` 而不是 `http` / `ws`：socket 的合法域名只认 `wss`，
真机对明文的容忍度也更低，走 https 少一层风险。

## 4. 接口调用的约定

后端已经实现，改前端时照这个来。

### 4.1 两条判断线都要处理

后端统一返回 `{ code, message, data }`，但**HTTP 状态码和 body.code 都要看**：

- `ErrorCode.httpStatus()` 里 `default -> HttpStatus.OK` ——
  **除 401 / 403 / 404 / 500 之外的业务错误都走 HTTP 200**，错误码只在 body 的 `code` 里；
- 因此 `request.js` 里有两条判断线：先看 HTTP 状态码，再看 `body.code`；
- `request.js` 还兼容后端**直接返回裸数据**（不带 `code`）的情况。

### 4.2 ⚠️ 401 分支会丢掉后端的 message（已知取舍）

`request.js` 的 401 分支做了两件事：**清本地 token** + 抛出固定文案
「登录已失效，请重新登录」。也就是说**后端的 `message` 在这个分支被丢弃了**。

管理端 `library-admin/src/utils/request.js` 踩过同一个坑（已修）：它当时丢掉了 message，
页面只显示 axios 的原文 "Request failed with status code 401"，看不出真实原因。
**改错误提示时记住这个模式：HTTP 状态码分支必须把 body.message 带出去。**

> 小程序这边**已经改成带 message 了**（2026-09-30）：401 分支现在是
> `reject(makeError(401, body.message || '登录已失效，请重新登录', 'unauthorized'))`。
> 不改不行 —— 登录 / 注册接口的 401 是「学号或密码错误」，一律改写成"登录已失效"
> 会让用户在登录页上完全看不懂发生了什么。业务接口的 401 后端给的是
> 「登录已过期，请重新登录」，语义也对得上。

### 4.3 其他约定

| 项 | 约定 |
| --- | --- |
| 字段命名 | 后端统一 snake_case；`api.js` 兼容 camelCase 只是兜底，不是鼓励 |
| 时间格式 | REST 是 `yyyy-MM-dd HH:mm:ss` 字符串；**WebSocket 的 `timestamp` 是 epoch 秒**，两种别混用 |
| 创建预约 | **只入参 `seat_id`**，没有时段概念（规范 14.3） |
| 取消预约 | 只能取消 `RESERVED`；已签到的要离座得走 `release` |
| 预约列表筛选 | `FINISHED` 是**后端归并** `COMPLETED + CANCELLED + TIMEOUT`，别在前端自己筛 |
| 预约动作返回值 | 四个动作都返回**操作后的完整 ReservationVO**，页面直接拿它刷新，不用再拉一次详情 |

## 5. WebSocket 的注意事项

### 5.1 token 只能放查询参数

小程序的 `wx.connectSocket` 和浏览器的 WebSocket **都不能自定义请求头**，
所以 JWT 只能挂在 `?token=` 上。后端 `TokenHandshakeInterceptor` 在**握手阶段**校验，
无效直接 403，客户端连 `onOpen` 都收不到。

> 这也是为什么"先连上再关掉"的做法不可取 —— 界面会闪一下"已连接"再断开，
> 用户体验上像故障。握手期拒掉是最干净的。

### 5.2 只有三种消息，没有 `RESERVATION_UPDATE`

后端只发 `SEAT_UPDATE` / `DEVICE_STATUS` / `ALARM`。
规范 §18.4 里列过 `RESERVATION_UPDATE`，但**后端刻意不发**：
订单的每次跃迁必然伴随座位状态变化，`SEAT_UPDATE` 是它的严格超集。
所以**想实时刷新自己的订单，就按 `seat_id` 对上自己那几单所在的座位**。

另外 `WsMessage` 上有 `@JsonInclude(NON_NULL)` ——
**没赋值的字段不会出现在 JSON 里**，删掉这个注解会把接收端的增量合并逻辑打坏。

### 5.3 三条使用原则

1. **推送只当"该刷新了"的信号，不当数据源。** 页面收到消息后回去调 REST 重拉，
   数据库才是事实来源；消息乱序或丢失都不会让界面显示错数据。
2. **一次只维持一条连接。** 全馆状态是广播给所有人的，多开只是重复消费。
   一个小程序同时最多 5 个 socket，别浪费在同一个广播上。
3. **退出登录必须 `ws.close()`。** 后端按握手那一刻的 token 认人，
   不关连接的话换账号后旧会话的广播还会继续打过来。
   `app.js` 的 `clearSession()` 里已经调了。

### 5.4 页面必须退订

`ws.subscribe(handler)` 返回一个**取消订阅函数**，页面要在 `onUnload` 里调用它，
否则页面销毁后回调还会打进来，报 **`setData on destroyed page`**。

目前订阅的三个页面（首页、座位页、我的预约）都做了这件事，新增订阅页面时别忘。

### 5.5 后端不发心跳

所以**半开连接检测不到**（对端断了但没收到 close 帧）。真出现这种情况的表现是
**"页面不再自动刷新"，而不是"显示错误数据"** —— 页面 `onShow` 和下拉刷新仍然会拉全量。
要做真正的双向心跳得后端配合，超出规范 §18 的报文定义，属于刻意不做。
`utils/ws.js` 的重连策略：**2 秒起步、逐次翻倍、封顶 20 秒**，连续失败 5 次后暂停
（下次进页面 `ensure()` 时计数清零再试）。

### 5.6 不要按固定频率刷全量

座位页与我的预约页收到消息后**合并 400ms** 再重拉 ——
一次全馆状态变化可能连着推好几条，不合并会连打多次接口。
首页更省：只重拉 `GET /api/reservations/current`，不重绘整页。
签到页不订阅，它自己每秒 tick 一次倒计时，并在**待签到期间每 3 秒**轮询一次接口
（因为签到是读卡器触发的，页面上没有可点的按钮）。

```bash
PY=~/.workbuddy/binaries/python/envs/default/Scripts/python.exe
NODE=~/.workbuddy/binaries/node/versions/22.22.2-3/node.exe

$PY   _tools_check_miniprogram.py   # 静态校验

```

### 8.3 后端环境变量配在哪

`application.yml` 里敏感配置全是 `${ENV:默认值}` 形式，**缺哪个就走默认值**，
最常见的症状是 `Access denied for user 'root'@'localhost' (using password: YES)`
（默认密码 `root` ≠ 真实密码 `123456`）。

- **IntelliJ IDEA 跑**（本机唯一方式）→ **Run Configuration 的 Environment variables**
  一栏填（Run → Edit Configurations → `LibrarySeatApplication`）。

常用键：`MYSQL_PASSWORD`、`JWT_SECRET`、`ONENET_API_KEY`（只影响下行）、
`ONENET_PUSH_SECRET`（**要在 OneNET 数据推送也带上同值之后**再设，否则推送会被 401 拒）。

> ⚠️ `.idea/workspace.xml`（存 Run Configuration 的地方）里有**明文**的 `MYSQL_PASSWORD`。
> `.gitignore` 挡住了它不进仓库，但**打包成 zip 交付时会带上** —— 交给别人之前记得清一遍 `.idea/`。
> （`WECHAT_APP_SECRET` 自 2026-09-30 起已用不到，见到就删。）

### 8.4 两个本机怪癖

- **本机 Bash 先补 PATH**：`export PATH="/usr/bin:/bin:/c/Windows/System32:$PATH"`，
  否则会报 `dirname: command not found`；
- **不要用 heredoc 传多行脚本**（`cat <<'EOF'` / `python - <<'PY'` 在这个环境会被破坏），
  一律先落成文件再执行。
