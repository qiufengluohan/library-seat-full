# 06 · 答辩要点与演示脚本

---

## 1. 一句话讲清楚小程序端做了什么

> 「小程序是学生侧的唯一入口：它把后端给出的 **5 种座位业务状态** 呈现出来，
> 把 **RFID 刷卡签到** 的等待与结果如实展示，并让学生完成 **暂离 / 回座 / 离座** 三个动作。
> 小程序不直连物联网平台、不保存任何业务数据 —— 设备上报的原始数据（压力、红外）
> 只由后端处理，一切业务状态由后端决定。」

## 2. 四端边界（最常被追问）

| 端 | 只做什么 |
| --- | --- |
| STM32 | 感知与执行：采集压力 + 红外、双传感器融合、报警、OLED、读卡 |
| ESP8266 | 联网与转发：Wi-Fi、MQTT、断线重连 |
| OneNET | 物联网接入：设备身份、物模型、消息转发、指令下发 |
| **Spring Boot** | **全部业务逻辑**：用户、预约、状态机、超时、统计、WebSocket、设备接入 |
| **MySQL** | 持久化 9 张表 |
| **小程序** | 展示、点击、请求后端、更新页面 |

一句话：「OneNET 只管设备进后端这一段；小程序的对面只有一个 Spring Boot。」

## 3. 状态机（背下来，必问）

```
FREE ──预约──▶ RESERVED ──RFID签到──▶ USING ──▶ COMPLETED ──▶ FREE
                                        ├──暂离──▶ AWAY ──回座──▶ USING
                                        ├──离座──▶ COMPLETED
                                        └──压力存在+红外无人──▶ ALARM ──回座/消警──▶ USING

超时：RESERVED 15 分钟未签到 → TIMEOUT → FREE
      AWAY 30 分钟未回座     → COMPLETED → FREE
取消：RESERVED → CANCELLED → FREE
强释：RESERVED / USING / AWAY / ALARM → FREE
```

要点：**设备离线不是座位状态**，是独立的 `online` 标志，只加角标。

## 4. 演示脚本

前提：MySQL 已建 9 张表、Spring Boot 已启动、小程序 `baseUrl` 已配置、
节点已上电连上 MQTT、校园卡已在 Web 端绑定到当前账号。

| 步骤 | 操作 | 要讲的话 |
| --- | --- | --- |
| 1 | 打开小程序 → 登录页 | 「登录页只有微信登录一个按钮 —— 不收集头像和昵称」 |
| 2 | 点「微信一键登录」 | 「wx.login 拿到 code，后端用 code 换 openid 存入 user 表，作为账号唯一标识，并签发 token」 |
| 3 | 首页 | 「首页是静态总览。注意现在**没有**『当前预约』卡 —— 这是首次进入的状态，预约成功后它才会动态出现」 |
| 4 | 点「进入座位图」→ 座位页 | 「座位图 5 色：空闲绿、已预约黄、使用中红、暂离灰、红闪异常；座位状态来自 seat 表，设备离线是独立角标」 |
| 5 | 切换到另一间阅览室 | 「阅览室不做独立表，是后端按座位的 area + floor 归并出来的」 |
| 6 | 点一个绿色座位 → 确认弹窗 | 「创建预约只提交 seat_id，没有时段概念」 |
| 7 | 确认 → 预约成功页 | 「状态 RESERVED，倒计时 15 分钟到自动释放」 |
| 8 | 返回首页 | 「『当前预约』卡出现了 —— 它是有进行中预约时才渲染的」 |
| 9 | 点「去签到 / 离座」→ 签到页 | 「这一页**没有签到按钮** —— 规范里 RFID 签到不是学生端手动调用的」 |
| 10 | **拿校园卡在座位上刷一下** | 「读卡器 → OneNET → 后端 RFIDService.signIn：查卡号得到用户、找到他 RESERVED 的订单、改成 USING 并写 sign_time。当前预约决定了他签到的是哪个座位」 |
| 11 | 等页面自动刷新为「使用中」 | 「签到完成，学生在小程序上什么都没点」 |
| 12 | 点「暂离」→ 确认 | 「USING → AWAY，倒计时切到暂离剩余 30 分钟」 |
| 13 | 点「我已回座」 | 「AWAY → USING」 |
| 14 | 点「离座」→ 确认 | 「USING → COMPLETED，座位立即释放，同时生成 study_record 学习记录」 |
| 15 | 回座位页 | 「刚才那个座位已经从红色变回绿色」 |
| 16 | 我的 | 「账号信息、校园卡绑定全部来自数据表：openid 是账号标识、注册时间由数据库写入、校园卡号来自 rfid_user，未绑定就显示『暂无』」 |
| 17 | 在「我的」改昵称 → 保存 | 「只有昵称和头像可改，PUT /api/users/me」 |
| 18 | **拔掉节点电源，等 2 分钟** | 「座位出现『离线』角标 —— 它没有改变座位业务状态，离线是独立的 online 标志」 |
| 19 | **把书压在压力传感器上、人离开红外范围** | 「压力有值而红外持续无人，达到时间窗口后设备判为假占座」 |
| 20 | 看该座位 | 「变成红闪的异常状态 —— 这就是双传感器融合的价值：单靠压力会把书当成有人」 |

> 第 18～20 步是加分项；时间紧的话可以把假占座的时间窗口临时调到 1 分钟先跑一遍。

## 5. 四个亮点的讲解词

### 亮点 1：双传感器融合，减少假占座误判

「单靠压力会误判：书包放上去就以为有人。这里加了 HC-SR501 红外，
压力超阈值 **且** 红外持续无人达到时间窗口（3 分钟），才判为假占座并置 `alarm_flag`，
写入 `seat_shadow` 后由 `/api/seats` 带给小程序，以红闪的形式显示。」

### 亮点 2：完整的物联网链路

「FSR402 + HC-SR501 → STM32 → UART → ESP8266 → MQTT → OneNET → HTTP 推送 → Spring Boot。
**小程序不参与这一段**，它只面对后端的 REST 接口 —— 这也是规范定的边界：
设备层的事归设备层，业务层的事归后端。」

### 亮点 3：RFID 自动签到

「RFID 是共享读卡器，它不选座位，只证明『这个人到了』。
读卡器读到 UID → OneNET → 后端查 `rfid_user` 得到 user_id → 查该用户 RESERVED 的订单 →
改成 USING 并写 `sign_time`。**当前预约决定他签到的是哪个座位**。」

### 亮点 4：职责清晰的前后端分离

「小程序的网络请求只出现在 `utils/request.js` 一个文件里；
页面统一走 `utils/api.js`，页面代码里不出现任何接口路径和字段名。
后端即使把字段从 snake_case 改成 camelCase，也只需要改 `api.js` 的归一化层，8 个页面一行都不用动。」

## 6. 可能被追问的问题

| 提问 | 回答要点 |
| --- | --- |
| 小程序为什么不直连 OneNET？ | OneNET 的应用侧接口需要把鉴权签名串放在客户端，会被反编译拿到；而且业务规则（预约、状态机、超时释放）必须在后端。规范也把小程序限定为「只看后端给的状态」 |
| 为什么小程序里没有任何初始数据？ | 数据只有两个来源：数据库和后端接口。没有数据就显示空态。之前版本有本地数据集，会出现"没接后端却能预约"的假象，已经删掉了 |
| 微信登录为什么拿不到昵称和头像？ | 微信 2022 年后收紧了用户信息接口，`getUserProfile` 不再返回真实昵称头像。现在要么用 `chooseAvatar` + `type="nickname"` 让用户手动填，要么默认空。我们选了后者，昵称默认「微信用户」，可在「我的」页自改 |
| 微信号能拿到吗？ | 拿不到，官方没有这个接口。能拿到的唯一身份标识是 `openid`，所以账号以 `openid` 为准 |
| 设备离线怎么处理？ | 独立 `online` 字段 + 角标；后端按 `last_report_at` 超过 120 秒判定，设备 60 秒一次心跳，允许丢一次包 |
| 断网了怎么办？ | ESP8266 自动重连，STM32 继续本地感知与报警；恢复后重连 MQTT 上报最新状态，后端以最新状态为准，不做复杂历史缓存 |
| 为什么不用 Redis / EMQX？ | 规范第 49 条删除清单明确不要。超时释放用 `@Scheduled` 每分钟扫表即可，也更好调试和答辩 |
| 小程序端能改校园卡号吗？ | 不能。`rfid_user` 由管理端维护，小程序只读，避免把卡绑到别人账号上 |
| 学习时长怎么算？ | `study_record.start_time = 签到时间`，`end_time = 离座时间`；暂离不拆段（规范第四十三节的最简方案） |
