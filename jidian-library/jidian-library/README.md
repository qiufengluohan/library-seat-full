# jidian-library · 图书馆座位预约与学习管理小程序

> 毕业设计 ｜ **微信小程序端**（原生 WXML / WXSS / JavaScript）
> 架构：小程序 **只与自建 Spring Boot 后端通信**，不直连 OneNET，不保存任何业务数据

---

## 一、这个工程是什么

本工程是**小程序端**的完整交付物，按《实际编码规范_最终版》与《四端统一最终方案》实现。

```
STM32 + 压力传感器 + 人体红外 + RFID
        ↓ UART
ESP8266  ↓ MQTT
OneNET（物模型 + 设备身份）
        ↓ HTTP 推送
Spring Boot（全部业务逻辑）
        ↓                    ↑
     MySQL            HTTPS │ 微信小程序（学生侧）
```

- OneNET 只承担「设备 → 后端」这一段；
- 小程序侧的座位状态、预约、用户资料、校园卡绑定，**全部来自后端接口**；
- 后端地址未配置或服务没起时，小程序**不发起任何请求、也不允许预约**，只给出空态提示。

**8 个页面**，只做一件事：把后端给出的状态如实呈现，并让学生完成预约与座位操作。

## 二、快速开始

### 1. 配置后端地址

打开 `miniprogram/utils/config.js`，把 Spring Boot 的地址填进 `server.baseUrl`：

```js
server: {
  baseUrl: 'http://localhost:8080',   // ← 局域网真机调试改成 http://192.168.x.x:8080
  timeout: 10000,
  tokenKey: 'jidian_token'
}
```

### 2. 导入小程序

1. 微信开发者工具 → 「导入项目」；
2. 目录选择本工程**根目录**（`miniprogramRoot` 已在 `project.config.json` 里指向 `miniprogram/`）；
3. AppID 填自己的，或点「测试号」；
4. 若用 HTTP 地址调试，在「详情 → 本地设置」勾选**「不校验合法域名」**；
   上线前需把域名加入微信公众平台的 **request 合法域名**。

### 3. 启动后端

后端按 **[docs/04-小程序端接口契约](docs/04-小程序端接口契约.md)** 实现，共 12 个接口。
后端没起或没数据时，各页面会显示明确的空态，不会出现假数据。

### 看全页面设计

浏览器直接打开 **[preview/index.html](preview/index.html)** —— 8 个页面的静态可视化预览。

## 五、核心机制

### 1. 座位状态只有 5 种，离线是独立标志

```
0 FREE      空闲    绿
1 RESERVED  已预约  黄
2 USING     使用中  红
3 AWAY      暂离    灰
4 ALARM     异常    红闪
设备离线 → 独立的 online 标志，只加「离线」角标，不覆盖业务状态
```

### 2. 预约状态只有 6 种

`RESERVED` / `USING` / `AWAY` / `COMPLETED` / `CANCELLED` / `TIMEOUT`

### 3. 状态机

```
FREE ──预约──▶ RESERVED ──RFID签到──▶ USING ──▶ COMPLETED ──▶ FREE
                                        ├──暂离──▶ AWAY ──回座──▶ USING
                                        └──离座──▶ COMPLETED
超时：RESERVED 15 分钟未签到 → TIMEOUT ；AWAY 30 分钟未回座 → COMPLETED
异常：USING ──压力存在+红外无人──▶ ALARM ──回座/消警──▶ USING
```

**RFID 签到由设备触发**（读卡器 → OneNET → 后端），小程序端不提供签到按钮；
学生端只做暂离 / 回座 / 离座。

### 4. 前端不做传感器判断

小程序只显示后端给的 `seat.status`、`alarm`、`online`；
压力值与红外状态属于设备层，小程序端不参与判断。

### 5. 网络边界

全工程**只有 `utils/request.js`** 允许出现 `wx.request`；
页面统一通过 `utils/api.js` 取数，页面代码里不出现接口路径与字段名。
后端改了字段命名风格，只需要动 `api.js` 的归一化，页面不用改。

## 六、账号与校园卡

| 项 | 说明 |
| --- | --- |
| 用户标识 | 微信登录后用 `openid` 作为账号唯一标识，存入 `user.openid` |
| 昵称 | 微信登录**不提供**昵称，表里默认为空，界面展示「微信用户」，用户可在「我的」页自改 |
| 头像 | 同上，默认为空，可在「我的」页点头像更换，存入 `user.avatar_url` |
| 校园卡号 | 来自 `rfid_user` 表，**只读**；未绑定时显示「暂无」，绑定与解绑由管理员在 Web 端完成 |
| 注册时间 / 更新时间 | 来自 `user` 表的 `created_at` / `updated_at`，由后端维护，只读 |

> ⚠️ 微信小程序**拿不到用户的微信号**（官方没有这个接口），能拿到的唯一身份就是 `openid`。

## 九、相对上一版的变更（本轮）

### 架构调整

- **小程序不再直连 OneNET**：删除 `utils/onenet.js`、`utils/thingModel.js`，
  改为 `utils/request.js` 统一请求 Spring Boot；
- **删除本地数据集** `utils/staticData.js`：所有业务数据以后端为准，
  没有后端就没有数据、也**不能预约**（之前"没接云端却能预约"的问题由此解决）。

### 页面调整

- 登录页改为**仅微信登录**：删掉「使用已有账号进入」（未登录也能点进去的漏洞）、
  删掉头像与昵称收集；
- **删除个人信息页**，把编辑资料融合进「我的」页；
- **删除学习统计页**（首页宫格入口与「我的」效率指标一并删除后，该页已无入口）；
- 「我的」页字段全部绑定数据表，表里没有值就留空；
  校园卡号未绑定显示「暂无」；删掉「绑定时间」之外的编造字段；
- 首页删除公告轮播（没有对应的数据表与接口）。

### 文案修正

- 校园卡说明改为：「校园卡号为座位上RFID读卡器读到的卡号是刷卡签到的唯一凭证。绑定与解绑由图书馆管理员完成。」
