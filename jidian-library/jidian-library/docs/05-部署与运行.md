# 05 · 部署与运行

---

## 1. 目录说明

```
jidian-library/
├── miniprogram/            微信小程序源码（本工程的主体交付物）
├── preview/index.html      8 个页面的静态可视化预览（浏览器直接打开）
├── docs/                   6 篇设计文档
├── project.config.json     微信开发者工具工程配置
├── project.private.config.json
└── README.md
```

> 另外三端（STM32 固件 / Spring Boot 服务端 / Vue3 Web 管理端）由本人独立实现，不在本包内。
> 小程序依赖后端的接口清单见 **[04-小程序端接口契约](04-小程序端接口契约.md)**。

## 2. 启动顺序

小程序不吃本地数据，所以**必须先起后端**：

```
1. MySQL 建库（执行 docs/02 里的 9 张表）
2. 启动 Spring Boot（默认 8080）
3. 确认后端接口能通：GET /api/seats 有返回
4. 小程序侧配置 baseUrl → 导入 → 运行
```

## 3. 配置小程序

`miniprogram/utils/config.js`：

```js
server: {
  baseUrl: 'http://localhost:8080',   // ← 后端地址；留空则小程序不发任何请求
  timeout: 10000,
  tokenKey: 'jidian_token'
}
```

| 场景 | baseUrl |
| --- | --- |
| 开发者工具本机调试 | `http://localhost:8080` |
| 真机预览（同一局域网） | `http://<电脑内网IP>:8080` |
| 线上 | `https://api.你的域名.com` |

## 4. 导入小程序

1. 微信开发者工具 → 「导入项目」；
2. 目录选择本工程**根目录**（`miniprogramRoot` 已在 `project.config.json` 里指向 `miniprogram/`）；
3. AppID 填自己的，或点「测试号」；
4. **若用 http 地址调试**：详情 → 本地设置 → 勾选「不校验合法域名」
   （这个开关同时管 `https://` 和 `wss://`，实时推送也就不用另外配了）；
5. `project.config.json` 里已预置 8 个编译模式（登录 / 首页 / 座位页 / 预约成功 / 签到 /
   我的预约 / 我的 / 意见反馈），切换后可直接跳到对应页面调试。

| 编译模式 | 需要带的参数 |
| --- | --- |
| 预约成功 | `id=<预约ID>` |
| 签到 / 离座 | `id=<预约ID>` |

## 5. 上线前的域名配置

微信公众平台 → 开发 → 开发管理 → 服务器域名：

- **request 合法域名**：填后端域名（必须 https，且已备案、证书有效）；
- **socket 合法域名**：填**同一个**域名（`wss://后端域名`）。这是同一个页面上的另一个输入框，
  只配了上面那条的话，REST 全通、页面数据也正常，但**座位不会再自动刷新** ——
  握手被微信直接拦掉，控制台才会有一句 `connectSocket 报 404/无法连接`，很容易被忽略；
- 小程序不支持用 IP、不支持自签名证书。

## 6. 看全页面设计

浏览器直接打开 **`preview/index.html`**。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 页面提示「尚未配置后端地址」 | `config.js` 的 `server.baseUrl` 是空的 |
| 提示「网络不可达」 | 后端没启动 / 地址写错 / 没勾「不校验合法域名」 |
| 提示「登录已失效，请重新登录」 | token 过期或后端重启导致签发的 token 失效，重新登录即可 |
| 座位页显示「后端暂未返回任何座位数据」 | `seat` 表是空的，先导入座位数据 |
| 阅览室列表是空的 | 座位的 `area` / `floor` 字段为空，小程序靠这两个字段归并阅览室 |
| 座位图位置错乱 | `seat_code` 需要形如 `A4-101`（`-` 后的数字：前几位是行、最后两位是列） |
| 我的预约一直是空 | 数据库里本来就没有预约记录；小程序不会显示任何初始假数据 |
| 签到页停在「待签到」 | 读卡器没有上报 `rfid_scan`：检查 MFRC522 接线、卡号是否已在管理端绑定 |
| 点座位提示「该座位当前为…」 | 正常拦截：只有空闲且设备在线的座位可预约 |
| 「我的」页校园卡号显示「暂无」 | `rfid_user` 表里还没有绑定记录，由管理员在 Web 端绑定 |

## 8. 交付前建议自检

| 检查项 | 怎么查 |
| --- | --- |
| 页面注册完整 | `app.json` 的 `pages` 共 8 项，与 `pages/` 目录一一对应 |
| 网络边界 | 全工程只有 `utils/request.js` 出现 `wx.request` |
| 无本地假数据 | 工程里没有 `staticData.js` / `onenet.js` / `thingModel.js` |
| 无调试残留 | 全工程没有 `console.log` / `info` / `warn` / `error` |
| 状态取值 | 座位状态只用 0~4，预约状态只用 6 个字符串枚举 |
| 图标齐全 | `images/` 里只保留被引用到的 12 个 PNG |
| 接口契约一致 | 后端路径与字段与 [04-小程序端接口契约](04-小程序端接口契约.md) 一致 |
