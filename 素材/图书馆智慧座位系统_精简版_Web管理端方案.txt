图书馆智慧座位系统
毕业设计精简版：Web管理端方案

说明：
本方案从原Web管理端方案中精简整理。
目标是保留毕设需要的核心管理功能，删除生产环境中不必要的复杂权限、缓存、性能和设备管理功能。

============================================================
一、Web管理端总体定位
============================================================

Web管理端用于管理员统一查看和管理图书馆座位、设备、RFID、异常和统计数据。

基本架构：

Web管理端
    │ HTTP / WebSocket
    ▼
Spring Boot
    │
    ├── MySQL
    │
    └── OneNET

原则：

1. Web管理端不直接访问OneNET。
2. 所有业务操作经过Spring Boot。
3. 座位颜色使用后端合成状态。
4. 单一管理员，不设计普通管理员、超级管理员和复杂权限系统。
5. WebSocket用于实时更新座位、告警和设备状态。

============================================================

============================================================
六、座位管理
============================================================

座位以地图或网格形式显示。

状态颜色：

绿色 = 空闲
黄色 = 已预约/待签到
红色 = 使用中
灰色 = 暂离
红色闪烁 = 告警

离线设备增加“离线”标识。

点击座位显示：

座位编号
设备状态
当前状态
学生
预约时间
开始时间
学习时间

管理员操作：

[消除告警]
[强制释放]

重要规则：

1. 告警不会自动关闭订单。
2. 消警和强制释放是两个独立操作。
3. 前端不根据压力ADC自行判断颜色。
4. 座位业务状态由后端统一处理。

============================================================
七、设备管理
============================================================

设备编号
所属座位
在线状态
压力值
PIR状态

允许修改：

压力阈值
PIR保持时间

提供：

[测试蜂鸣器]

不做：

OTA
固件升级
批量配置

============================================================
八、RFID管理
============================================================

显示：

学生
学号
RFID UID
绑定状态

操作：

绑定
解绑

绑定规则：

一人一卡；
一张卡只能绑定一个学生；
同一绑定重复提交可以保持幂等；
发生冲突时不能直接覆盖，需要先解绑。

RFID只用于识别学生，不直接决定座位。

学生当前订单决定其对应座位。

============================================================
十、WebSocket实时更新
============================================================

WebSocket地址：

/ws/seats

用于实时推送：

预约
签到
暂离
回座
离座
超时
告警
消警
设备上线
设备离线
强制释放

基本流程：

Spring Boot状态变化
        ↓
WebSocket
        ↓
Web管理端
        ↓
更新对应座位

不设计复杂的：

指数退避
visibilitychange
复杂防抖
大规模座位性能优化
复杂Pinia Map优化

断线后简单延时重连即可。

============================================================
十一、Web管理端API
============================================================

管理员：

POST /api/admin/login

Dashboard：

GET /api/admin/dashboard

座位：

GET /api/admin/seats
GET /api/admin/seats/{id}
POST /api/admin/seats/{id}/clear-alarm
POST /api/admin/seats/{id}/force-release

设备：

GET /api/admin/devices
POST /api/admin/devices/{id}/config
POST /api/admin/devices/{id}/buzzer

RFID：

GET /api/admin/rfid-binds
POST /api/admin/rfid-binds
DELETE /api/admin/rfid-binds/{uid}

违规：

GET /api/admin/violations

统计：

GET /api/admin/statistics

WebSocket：

/ws/seats

所有管理接口需要管理员Token。

OneNET密钥不能放在前端。

============================================================
十二、座位状态展示规则
============================================================

建议前端只负责展示后端提供的业务状态。

例如：

status=0 → 绿色
status=1 → 黄色
status=2 → 红色
status=3 → 灰色
alarm=true → 红色闪烁

设备offline：

在座位上增加离线标识。

前端不读取ADC后自己判断“有人/无人”。
