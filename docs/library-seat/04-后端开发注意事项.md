## 1. 三条不能破的约定

### 1.1 Jackson 的 snake_case

```yaml
spring:
  jackson:
    property-naming-strategy: SNAKE_CASE
```

编码规范 §4 规定 JSON 统一 snake_case。Spring Boot 默认输出 camelCase，
**一旦改掉或漏配，`device_id` 会变成 `deviceId`，小程序和 Web 管理端同时解析失败**，
OneNET 推送进来的数据也无法映射到 DTO。四端里三端要同时跟着改，代价极大。

有三处连带影响，**改这一条配置时容易漏**：

| 连带点 | 说明 |
| --- | --- |
| `@RequestParam` 的参数名 | **`SNAKE_CASE` 管不到查询参数名**，所以要显式写 `@RequestParam(name = "seat_id")`。漏了就变成 `seatId`，前端传的值收不到 |
| `WebSocketService` | 必须**复用**这个 `ObjectMapper` 序列化广播消息，自己 new 一个就会发出 `seatId` |
| `GlobalExceptionHandler` | 校验失败时回给客户端的字段名，要用 `wireName()` 过一遍**实际生效**的命名策略。曾经回过 `seatId 不能为空`（注解挂在 Java 字段上），而客户端发的是 `seat_id` |

### 1.2 HTTP 状态码：只有 401 和 500 用真实状态码

`ErrorCode.httpStatus()` 里定死的规则：**只有 401 和 500 用真实的 HTTP 状态码**，
400 / 403 / 404 / 409 一律返回 **HTTP 200 + 响应体里的 `code`**。

```json
HTTP/1.1 200
{"code":403,"message":"需要管理员权限","data":null}
```

管理端的 `request.js` 就是按这个约定写的 —— `error.silent = body.code === 409`
这行代码在 axios 的**成功**拦截器里。改成"用真实 HTTP 状态码"会让 409 冲突提示
从静默变成弹错误框，业务判断（预约冲突、重复绑卡）**全部走错分支**。

> 另一处相关的坑：**凭据错误（密码打错、密码带尾随空格）返回的是 HTTP 401**，
> 和 token 过期在状态码上完全一样，只能靠 body 里的 `message` 区分。
> 所以前端必须把 `message` 显示出来。小程序端目前 401 分支丢了 message
> （见 [../jidian-library/04-小程序开发注意事项](../jidian-library/04-小程序开发注意事项.md) §4.2），
> 管理端已经修好了。

### 1.3 分层铁律（编码规范 §18）

```
Controller → Service → 业务处理 → MySQL → WebSocket
```

- 禁止 Controller 直接调 OneNET、直接改数据库、直接发 WebSocket；
- 禁止把预约状态机写在 Controller 里；
- **前端绝对不能直接拼 OneNET 请求**（§42 / §53）。管理端点"下发阈值"时，
  请求打到 `/api/admin/devices/{id}/config`，由 `DeviceService` 翻译成 OneNET 属性下发。
  **api-key 永不出后端进程。**

## 2. 日志里绝不能出现的东西

这些是"打出来就等于泄露凭证或权限"，加日志时务必绕开：

| 内容 | 为什么 | 现在防在哪 |
| --- | --- | --- |
| OneNET `authorization` 头 | 一个有效 token 等于对所有设备的 api-key 使用权 | `OneNetDownlinkServiceImpl.post` |
| 学生 `password`（明文） | 密码进了日志就等于泄露账号 | 从不打日志；登录 / 注册只记 `studentNo` 与 `userId` |
| 学生 `password` 的 BCrypt 哈希 | 拿到哈希可以离线爆破 | 任何 VO 都不含这个字段 —— `vo/UserVO`、`vo/StudentLoginVO` 里根本没有定义它 |
| 学生 `password_plain`（**明文列**） | 读到明文等于直接拿到账号，比哈希危险得多 | **只允许在数据库客户端里人工排障时看**：不进任何 VO、不进日志、管理端不展示、不能出现在接口 URL 里。生产部署前 `DROP COLUMN password_plain` |
| 推送密钥的值 | 等同于伪造设备数据的权限 | `JwtInterceptor.checkPushSecret`，只记"有没有带" |
| `AdminUser.password` | —— | 任何 VO 都不含这个字段；登录失败统一回"用户名或密码错误"，**不区分**用户不存在和密码错 |

排查问题需要看原始报文时，看 `OneNetServiceImpl.normalize` 那条 DEBUG
（它打的是**设备报文**，不含任何凭证），不要顺手把请求头也打出来。

## 3. 定时任务的坑

两个任务都是 `@Scheduled(fixedDelay = 60_000)`：`ReservationTimeoutTask`、`DeviceOfflineTask`。
Spring 默认调度器**只有一个线程**，所以它们天然串行，不会互相打断。

| 坑 | 说明 |
| --- | --- |
| **两个任务都刻意不加 try/catch** | Spring 的调度器会捕获异常、记 ERROR、然后照常安排下一次。实测数据库连不上时每 60 秒稳定失败一次，但巡检从不停摆。**别"顺手"包一层 try/catch** —— 那会让真正的故障被吞掉 |
| **离线巡检只碰 `seat_shadow`** | 离线**不是座位状态**（§5.3 / §39）。`SeatStatus` 只有 0-4 五个值，离线是影子表上的附加标记，前端渲染成角标。所以巡检绝不能去改 `seat` 表 |
| **必须用条件更新** | `markOfflineIfStale` 写的是 `WHERE id=? AND online=1 AND last_report_at<?`。不要改成"先查后无条件 `updateById`" —— 查和改之间设备可能刚好上报了一条，无条件更新会把一台活着的设备标成离线，最长要等下一轮才恢复 |
| 用轮询而不是延迟队列 | Redis 延迟队列在编码规范 §49 删除清单里。`fixedDelay` 每分钟扫表在毕设规模下够用，也更好调试和答辩 |

## 4. OneNET 相关的坑

### 4.1 上行：只记 WARN，绝不抛

**"处理不了"和"这次没处理成"要分开：**

- 报文本身有问题（`device_name` 查不到座位、字段缺失、结构不认识）→ **只记 WARN 就返回**。
  抛出去就是 500，OneNET 会把一条永远处理不了的数据**反复重推**；
- 数据库连不上这类**临时**故障 → 让它正常抛，平台重推一次就好了。

共享读卡器 `READER_01` 不占座位，它的 `rfid_scan` 走到"查不到座位"那条 WARN 是**正常现象**，
不是 bug —— 排查时看到它别去改代码。

### 4.2 字段名是 `device_name`，不是 `deviceName`

设备上报的字段名写成驼峰的 `deviceName` 会被**静默丢弃**，接口照样返回 200。
**所以不能拿 200 当通过，要回查 `seat_shadow` 表**确认值真的写进去了。

### 4.3 下行：返回 200 不代表设备收到

下发是 `@Async` 且**失败不影响业务**：只记日志，不回滚状态，不让接口报错。
所以 `/config` 和 `/buzzer` 返回 200 **只代表指令已经交给平台**。
设备有没有真的收到，看影子表里下一次上报的值。

自测方式：管理端点一次"测试蜂鸣器"，看设备是否真响；返回 200 但没反应，先查
`onenet.property-set-path` / `service-invoke-path` 是不是写错了。

### 4.4 token 签名两个最容易错的点

`util/OneNetTokenUtil`：

1. 待签串是四段用 `\n` 连接的**固定顺序** `et\nmethod\nres\nversion` ——
   顺序记错，平台一律返回 401 且**不告诉你哪段错了**；
2. HMAC 的密钥**不是 api-key 原文**，而是它 **base64 解码后的字节** ——
   漏掉这一步签名永远不对，而且看起来"格式是对的"，极难排查。

两点都有测试钉着，含一个用 node 独立算出来的黄金向量。改这个工具类必须让测试全绿。

### 4.5 Studio 的 API 路径开发期验证不了

所以在 `application.yml` 里**全部留成配置**（`property-set-path` / `service-invoke-path`）。
真机返回 404 时改一行配置即可，不用改 Java、不用重新编译。

## 5. 环境变量：配在 IDEA 的 Run Configuration 里

`application.yml` 里敏感配置全是 `${ENV:默认值}` 形式，**缺哪个就走默认值**，
最常见的症状是 `Access denied for user 'root'@'localhost' (using password: YES)`
（默认密码 `root` ≠ 真实密码 `123456`）。

**本机只用 IntelliJ IDEA 启动后端**（`.vscode/` 已删除，不要再找 `launch.json`）：

| 启动方式 | 环境变量写在哪 |
| --- | --- |
| **IntelliJ IDEA** ★ | Run → Edit Configurations → `LibrarySeatApplication` → **Environment variables** 一栏填 `MYSQL_PASSWORD=123456;ONENET_API_KEY=xxx` |
| 临时终端 | `export` / `$env:`，**只对当前窗口有效** |

IDEA 的 Run Configuration 存在 `library-seat/.idea/workspace.xml`（已 gitignore），
**再打开项目时配置会保留**；如果配置莫名丢失，就是 workspace.xml 被覆盖了，重填即可。

另外：用 `setx` 写进注册表的值，**已经开着的 IDEA / 终端读不到**，得重启那个程序。

缺哪个会在启动日志里看到对应 WARN（OneNET 下行、`/api/onenet/**` 鉴权都会自检）。

> ⚠️ `library-seat/.idea/workspace.xml` 里有**明文**的 `MYSQL_PASSWORD`。
> `.gitignore` 挡住了它不进仓库，但**打包成 zip 交付时会带上** —— 交给别人前记得清一遍 `.idea/`。
> （`WECHAT_APP_SECRET` 自 2026-09-30 起已用不到，见到就删。）

## 6. 构建与环境

### 6.1 JDK 27 工具链 + Java 17 编译目标（两件事，别一起改）

后端的 Java 版本是**故意分开**的两个东西，混起来改会踩坑：

| 项 | 值 | 在哪 |
| --- | --- | --- |
| **工具链 / 运行环境** | **JDK 27** | IDEA 的 Project Structure → SDK；`JAVA_HOME` |
| **编译目标（字节码）** | **Java 17**（class major **61**） | `library-seat/pom.xml` 的 `<java.version>17</java.version>`；Maven `settings.xml` 里 `activeByDefault` 的 `jdk17` profile（`maven.compiler.{source,target,release}` 三处都是 17） |

**为什么目标必须留在 17**：Spring Boot 3.2.5 内置的 ASM 只认到 class major 66，
**认不了 Java 27 的字节码（major 71）**。把目标设成 27 时 ——
`mvn compile` 能过，**应用一启动就直接失败**。所以「工具链 27 + 目标 17」是当前唯一能跑的组合。

> ⚠️ **两个来源会打架**：`settings.xml` 的 profile 是 `activeByDefault=true` 常驻生效的，
> 它设的 `maven.compiler.release` 与 pom 里的同名属性是**两个独立来源**。
> 以后要改 Java 版本，**两边必须一起改**；只改一边，另一边会静默覆盖掉你的改动。
> （`~/.m2/settings.xml` 只是 devtools 那份的副本，改完记得重新 cp 一次。）

### 6.1.1 跑在 JDK 27 上，Boot 3.2.5 的两个默认版本必须覆盖

这两条与"编译目标"无关，是**因为 JDK 27 这个运行环境**才需要的。回退会有明确症状：

| 依赖 | Boot 3.2.5 默认 | 本工程覆盖为 | 不覆盖会怎样 |
| --- | --- | --- | --- |
| **Lombok** | 1.18.32 | **1.18.48** | 只支持到 JDK 22。在 JDK 27 上**不报错**，而是**静默不生成 getter/setter** —— 编译照样 `BUILD SUCCESS`，**运行期才炸**。这个坑最阴 |
| **Byte Buddy** | 1.14.13 | **1.18.14** | 只认到 class 66。跑 Mockito 时直接拒绝：`Java 27 (71) is not supported by the current version of Byte Buddy`，实测 55 个用例挂 23 个 |

两处都是通过**覆盖 Boot 属性**的方式生效的（官方支持的覆盖方式，
`dependencyManagement` 里的 `byte-buddy` / `byte-buddy-agent` 会一起生效）：

```xml
<lombok.version>1.18.48</lombok.version>
<byte-buddy.version>1.18.14</byte-buddy.version>
```

> **以后升 Spring Boot 要重新核对这两个版本**，不要盲目沿用 Boot 的默认值。

### 6.1.2 剩下一条消不掉的 WARNING

那 4 条 `WARNING: System::load 是受限方法`（来自 Tomcat 的 `tomcat-embed-core`）
**依然存在** —— 它们来自"**运行在 JDK 27**"，与编译目标无关，换任何编译目标都消不掉，
不要指望靠调版本解决。

### 6.2 Maven 的两个坑

- 本地仓库缺 surefire 插件，**第一次跑 `mvn test` / `mvn package` 必须联网**，
  让它从 alimaven 下载；加 `-o` 会直接失败；
- `pom.xml` 的 **XML 注释里不能出现连续两个短横线**。写 `javac --release 27` 会导致 Maven 报
  `Non-parseable POM ... in comment after two dashes (--)`。
  校验办法：`python -c "import xml.etree.ElementTree as ET; ET.parse('pom.xml')"`。

## 7. 数据库与时间

| 坑 | 说明 |
| --- | --- |
| **小数秒会让 REST 与库差 1 秒** | MySQL 存进 `DATETIME(0)` 会四舍五入，Jackson 格式化会截断，同一个内存值能出两个结果（实测 `release_time` 比 `reserve_time` 早 1 秒）。所以时间一律走 `TimeUtil.now()` / `TimeUtil.fromEpoch()` 截到整秒 |
| MySQL 是 Windows 服务 `MySQL80` | root / `123456`，开机自启、不随会话回收。优雅停用 `net stop MySQL80`（硬杀后重启会报 `ibdata1 must be writable`）。**停之前先想清楚还要不要用** |
| Navicat 连不上 | 主机必须填 `127.0.0.1` 或 `localhost`（`bind-address=127.0.0.1` 只监听回环），填机器名 / 局域网 IP 会 `ERROR 2003 (10061)`。root 认证插件是 `caching_sha2_password`，**Navicat 需 12 以上** |
| 端口 8080 | 曾被 NI Application Web Server（LabVIEW 装进来的服务 `NIApplicationWebServer`）占用，已停掉并改成手动启动。回滚脚本在桌面 `restore-8080.bat`。**yml / README / vite 的 `BACKEND` / 小程序 `baseUrl` 四边都是 8080** |

## 8. 联调与交付自检

### 8.1 判断"服务活着"的最快方式

```bash
curl -i http://localhost:8080/api/seats
```

返回 **401 才是正常** —— 说明 JWT 拦截器活着、服务也活着。返回 200 反倒有问题。

### 8.2 不接硬件也能联调

用 Postman 直接打 `/api/onenet/device-data` 与 `/api/onenet/rfid-event`
（记得带推送密钥），就能把设备端和云端彻底解耦开调。
完整顺序见 [03-OneNET接入指南](03-OneNET接入指南.md) §7。

### 8.3 ⚠️ 两处"记得改回去"

| 位置 | 现状 | 说明 |
| --- | --- | --- |
| `application.yml` 的 `logging.level.com.example.libraryseat.service.impl` | **已是 `info`**（交付口径） | 联调设备上报、状态不更新时临时改成 `debug` 看原始报文，**联调完改回 `info`**。留着 debug 会把整段设备报文刷在日志里 |
| `Admin@123` 默认管理员密码 | 公开写在仓库里，开发演示用 | 公网部署前必须改（`02_seed.sql` 里有改法注释） |

### 8.4 交付前清单

1. `mvn clean test` —— 55 个用例全绿；
2. `mvn package` 能出 jar，`java -jar` 能起来；
3. 启动日志里没有 `未配置 onenet.push-secret` 之外的异常 WARN；
4. `application.yml` 里**没有任何真实凭证**（全部是 `${ENV:默认值}`）；
5. 全仓库 grep 一遍 `secret`、`api-key`、`password`、`Admin@123`，确认没有新的硬编码；
6. 上面 §8.3 那两处已确认（日志级别是 `info`、默认密码已改）。

## 9. 明确不做

完整清单（编码规范 §49）在 [01-后端说明](01-后端说明.md) §10。
这里只强调三个**不需要犹豫**的：

- **不引入 Redis**。超时释放用 `@Scheduled` 每分钟扫表即可；
- **不自建 EMQX**，不与 OneNET 双平台并行；
- **不做 RBAC**，只有 `STUDENT` / `ADMIN` 两种角色。
