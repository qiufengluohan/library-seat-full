智慧图书馆座位智能管理系统
实际编码规范（最终统一开发版）
============================================================

一、文档定位
============================================================

本文件是在《智慧图书馆座位智能管理系统_四端统一最终方案》基础上继续落地形成的“实际编码规范”。

依据：
1. 《代茂源_开题报告(1).docx》
2. 设备端方案_OneNET版
3. 云端接入方案_OneNET版
4. 小程序端方案_OneNET版
5. 图书馆智慧座位系统_精简版_Web管理端方案

本文件解决的问题：

1. Spring Boot到底建立哪些包和Java文件
2. MySQL到底建立哪些表
3. Entity、DTO、VO分别怎么划分
4. API到底有哪些，路径怎么统一
5. OneNET数据格式怎么统一
6. WebSocket消息怎么统一
7. STM32、ESP8266、云端、小程序、Web分别先写什么代码
8. 四端如何避免重复写业务逻辑
9. 哪些功能明确不再增加
10. 最终代码应该按照什么顺序开发

最终原则：

“一个功能只有一个业务归属，一个字段只有一种命名，一种状态只有一套定义。”

开题报告明确了STM32、压力传感器、人体红外、RFID、ESP8266、MQTT、Spring Boot、MySQL、微信小程序和Vue 3 Web管理端等主要内容。本编码规范沿用这些核心内容，并将原方案中Redis复杂队列、EMQX双平台、复杂权限等内容进行简化。

五、统一状态定义
============================================================

5.1 SeatStatus

FREE = 0
RESERVED = 1
USING = 2
AWAY = 3
ALARM = 4

含义：

0 FREE       空闲
1 RESERVED   已预约/等待签到
2 USING      使用中
3 AWAY       暂离
4 ALARM      异常告警


5.2 ReservationStatus

RESERVED
USING
AWAY
COMPLETED
CANCELLED
TIMEOUT


5.3 Device状态

online = true
online = false

设备离线不是SeatStatus。

前端显示：
seat.status + online + alarm。

六、统一业务状态机
============================================================

正常流程：

FREE
  │
  │ POST /api/reservations
  ↓
RESERVED
  │
  │ RFID签到
  ↓
USING
  │
  ├── 暂离 → AWAY → 回座 → USING
  │
  └── 离座 → COMPLETED → FREE


预约取消：

RESERVED → CANCELLED → FREE


预约超时：

RESERVED → TIMEOUT → FREE


暂离超时：

AWAY → COMPLETED → FREE


管理员强制释放：

RESERVED / USING / AWAY / ALARM
                    ↓
                   FREE


异常：

USING
  ↓
压力 > 阈值 + PIR持续无人
  ↓
ALARM


人员重新回座：

ALARM → USING

CREATE TABLE reservation (

十二、统一Result
============================================================

建议所有HTTP接口统一返回：

{
  "code": 200,
  "message": "success",
  "data": {}
}


Java：

public class Result<T> {

    private Integer code;

    private String message;

    private T data;

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "success", data);
    }

    public static <T> Result<T> success() {
        return new Result<>(200, "success", null);
    }

    public static <T> Result<T> error(String message) {
        return new Result<>(500, message, null);
    }
}


建议错误码：

200 成功
400 参数错误
401 未登录
403 无权限
404 数据不存在
409 业务冲突
500 服务器错误


预约冲突统一使用：

409


例如：

{
  "code": 409,
  "message": "座位已被预约",
  "data": null
}

十四、每个API具体干什么
============================================================

14.1 POST /api/auth/wechat-login

输入：

{
  "code": "微信code"
}

后端：
1. code换openid
2. 查询user
3. 没有则创建
4. 生成token
5. 返回LoginVO


14.2 GET /api/seats

返回全馆座位合成状态。

小程序只调用这个接口。

返回：

[
  {
    "seat_id": 1,
    "seat_code": "A1-001",
    "status": 0,
    "alarm": false,
    "online": true
  }
]


14.3 POST /api/reservations

输入：

{
  "seat_id": 1

@Transactional
public void createReservation(Long userId, Long seatId) {

    Seat seat = seatMapper.selectById(seatId);

    if (seat == null) {
        throw new BusinessException("座位不存在");
    }

    if (!seat.getStatus().equals(SeatStatus.FREE.getCode())) {
        throw new BusinessException("座位不可预约");
    }

    Reservation current =
        reservationMapper.findCurrentByUserId(userId);

    if (current != null) {
        throw new BusinessException("已有进行中的预约");
    }

    Reservation reservation = new Reservation();

    reservation.setUserId(userId);
    reservation.setSeatId(seatId);
    reservation.setStatus("RESERVED");
    reservation.setReserveTime(LocalDateTime.now());

    reservation.setReserveExpireAt(
        LocalDateTime.now().plusMinutes(15)
    );

    reservationMapper.insert(reservation);

    seat.setStatus(SeatStatus.RESERVED.getCode());

    seatMapper.updateById(seat);

    webSocketService.broadcastSeatUpdate(seatId);
}

二十二、RFID签到核心伪代码

public void signIn(String rfidUid) {

    RfidUser rfidUser =
        rfidUserMapper.findByUid(rfidUid);

    if (rfidUser == null) {
        return;
    }

    Reservation reservation =
        reservationMapper.findReservedByUserId(
            rfidUser.getUserId()
        );

    if (reservation == null) {
        return;
    }

    reservation.setStatus("USING");
    reservation.setSignTime(LocalDateTime.now());

    reservationMapper.updateById(reservation);

    Seat seat =
        seatMapper.selectById(reservation.getSeatId());

    seat.setStatus(SeatStatus.USING.getCode());

    seatMapper.updateById(seat);

    webSocketService.broadcastSeatUpdate(
        reservation.getSeatId()
    );
}

五十二、最终一句话开发规则
============================================================

STM32只负责“感知和执行”。

ESP8266只负责“联网和转发”。

OneNET只负责“物联网接入”。

Spring Boot负责“全部业务逻辑”。

MySQL负责“持久化”。

WebSocket负责“实时通知”。

微信小程序负责“学生操作和展示”。

Vue Web负责“管理员操作和展示”。

任何代码如果不知道应该写在哪里，就按照这八句话判断。


============================================================
五十三、最终架构冻结
============================================================

从现在开始：

旧方案与本文件冲突：

以本文件为准。

前端想增加业务：

先确认Spring Boot有没有对应业务。

Spring Boot想增加设备业务：

先确认是否属于设备层。

设备端想判断预约：

禁止。

小程序想判断压力：

禁止。

Web想直接调用OneNET：

禁止。

OneNET想处理预约：

禁止。

数据库想保存大量设备历史：

暂时禁止。

Redis想加入：

除非后续出现实际性能问题，否则禁止。

最终目标：

“结构简单、代码统一、功能完整、容易调试、容易写论文、容易答辩。”
