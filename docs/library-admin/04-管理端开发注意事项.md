# 04 · 管理端开发注意事项

> 这份文档不是说明书，是**约束清单**。上面每一条都对应一次踩坑或一次返工。
>
> 改管理端代码之前先扫一遍 §1（三条不能破的约束）；动接口调用看 §2；
> 动实时部分看 §3；启动不起来看 §4、§5。
>
> 想知道这一端负责什么、有哪几个页面，看 [01-管理端说明](01-管理端说明.md)。

## 1. 三条不能破的约束

### 1.1 禁止直连 OneNET / MQTT

依据《四端统一最终方案》§41 与《实际编码规范》§53：

> Web 想直接调用 OneNET：禁止。前端绝对不能直接拼 OneNET 请求。

- `package.json` 里**没有也不该有** `mqtt`、`crypto-js`、任何物联网平台 SDK；
- 设备控制一律走 `/api/admin/devices/**`、`/api/admin/seats/**`，由后端翻译成 OneNET 报文；
- **api-key / device_secret / push_secret 永不出后端进程。**

历史上有一份 `IoT云平台集成指南.md` 设计了"前端持有 `device_secret` 并用 MQTT 直连平台"，
那条路已被明确废弃，现在由 [../library-seat/03-OneNET接入指南](../library-seat/03-OneNET接入指南.md) 取代。

### 1.2 业务状态只由后端给，前端只做映射

前端**绝不**根据 `pressure_adc` / `pir_state` 反推座位状态。
状态码、颜色、标签、WS 消息类型的唯一定义处是
**`src/constants/status.js`** —— 页面里不许散落颜色值和中文状态名。

三条容易写错的细节：

1. **设备离线不是业务状态。** `online=false` 只渲染叠加的「离线」角标，**不覆盖**业务状态颜色。
   一个离线但上次是"使用中"的座位，仍然显示「使用中 + 离线角标」，**不能显示成空闲**；
2. **状态 `4` 是"异常告警"，要做闪烁**，改这个值会连带影响小程序的假占座提示；
3. **配色必须与小程序端一致**（0 绿 `#22C08A` / 1 黄 `#F5A623` / 2 红 `#F0554B` /
   3 灰 `#9AA4B8` / 4 红闪）。改一处要两端一起改。

### 1.3 `VITE_` 开头的变量会进前端 bundle

**`VITE_` 前缀的环境变量会被打进前端产物，等于公开泄露。**
所以 `.env.*` 里只允许出现"前端自己要知道的地址"：

```bash
VITE_API_BASE_URL=/api
# VITE_WS_BASE_URL=          # 留空 = 与页面同源，由 Vite 代理转发到 8080
```

OneNET 的 `product-id` / `api-key`、JWT 密钥、数据库口令**一律属于后端**，绝不能放进这里。
`.env.development` 顶部就写着这条注释，别删。

## 2. 请求层：两条判断线

这是整个管理端最容易写错的地方，`utils/request.js` 的两个拦截器要配合着读。

### 2.1 后端的错误码走 body，不全部走 HTTP 状态码

`ErrorCode.httpStatus()` 里定死的规则：**只有 401 和 500 用真实的 HTTP 状态码**，
400 / 403 / 404 / 409 一律返回 **HTTP 200 + 响应体里的 `code`**。

所以同一个"失败"有两副面孔，拦截器里必须**两条线都处理**：

| 线 | 在哪 | 表现 |
| --- | --- | --- |
| 成功拦截器 + `body.code` | `body.code !== 200` | HTTP 200，但 `code` 是 400/403/404/409 |
| 错误拦截器 + `error.response.status` | HTTP 不是 2xx | 只有 401 和 500 会走到这里 |

> 建议永远不要"改成用真实 HTTP 状态码" —— 那会让 409 的静默逻辑失效（见下条），
> 而且小程序端也要跟着改。

### 2.2 409 必须静默

```js
error.silent = body.code === 409
```

这一行在**成功**拦截器里。409 是预约冲突、重复绑卡这类**正常业务反馈**，
由调用方决定怎么提示；如果它也弹 `ElMessage.error`，管理员每点一次冲突座位都会吃一个红色错误框。

### 2.3 401 必须把后端的 `message` 带出去

401 在管理端有**两个完全不同的来源**，只能靠 body 的 message 区分：

| 来源 | 后端说法 |
| --- | --- |
| `POST /api/admin/login` 用户名或密码错（`AdminServiceImpl` 抛 `unauthorized`，错误码是 **401 不是 400**） | 「用户名或密码错误」 |
| 其它接口 token 缺失 / 过期 / 签名不符 | 「登录已过期，请重新登录」 |

`request.js` 的错误拦截器里因此写了：

```js
const text = bodyMessage || '登录已过期，请重新登录'
error.message = text
```

**这两行是补上一个真实踩过的坑**：原来直接 reject 原始 axios error，
页面只能拿到 `Request failed with status code 401`，用户完全看不出是密码打错了还是登录掉了，
只能来问人。**改错误提示时记住这个模式：HTTP 状态码分支必须把 `body.message` 带出去。**

两条附带说明：

- **密码不会被 trim** —— 尾随空格算进密码，就是密码错，不该"帮"用户去掉；
- 忘记这条规则的代价是隐形的：接口能通、代码不报错，只是提示语变成看不懂的英文。

### 2.4 其它两个细节

| 细节 | 原因 |
| --- | --- |
| `redirectToLogin()` 用 `window.location.assign('/login')` 整页跳转，而不是 `router.push` | 避免 `request ↔ router ↔ store` 循环依赖，同时把内存里的座位状态一并清掉。里面还有 `pathname !== '/login'` 的判断，防止在登录页上密码打错时把自己刷一遍 |
| 错误拦截器里**覆盖** `error.message` | 否则页面里的错误横幅会显示 axios 原文 `Request failed with status code 500`。覆盖成「无法连接后端服务，请确认 library-seat 已启动」这类人话 |

"后端连不上"的判定是 `!error.response || (status >= 500 && !bodyMessage)` ——
Vite 代理连不上后端时返回空 body 的 500，真实后端的 500 一定带 Result body，据此区分。

## 3. WebSocket 的约定

### 3.1 全局只应存在一个实例

`utils/websocket.js` 导出的是**单例** `seatWebSocket`，由 `stores/seat.js` 持有，
连接在 `components/Layout.vue` 建立。**不要在页面里自己 `new WebSocket`** ——
全馆状态是广播给所有人的，多开只是重复消费。

### 3.2 断线 3 秒固定重连，不做指数退避

编码规范 §38 明确：**3 秒后重连，重连成功重新拉一次座位列表，不做指数退避**。
所以 `RECONNECT_DELAY = 3000` 是**有意**写死的常量，别"优化"成指数退避
（小程序端那套 2 秒→20 秒的指数重连是另一份规范口径，两者**故意不同**）。

重连成功后会发 `reconnected` 事件（第一次是 `open`），store 据此重新拉一次列表 ——
这解决了"断线期间错过广播"的问题。

### 3.3 几条硬性约定

| 约定 | 原因 |
| --- | --- |
| **token 只能放查询参数**（`?token=`） | 浏览器的 `WebSocket` 不能自定义请求头。后端在**握手阶段**校验，无效直接 403 |
| **退出登录必须 `close()`** | 后端按握手那一刻的 token 认人，不关连接的话换账号后旧会话的广播还会继续打过来。`close()` 里同时清了各种 `on*` 回调并置 `manualClose=true`，否则 `onclose` 会触发重连 |
| **消息 `type` 只认三种** | `SEAT_UPDATE` / `DEVICE_STATUS` / `ALARM`。后端**刻意不发** `RESERVATION_UPDATE`（编码规范 §18.4 列过），收到未知 type 只会 `console.warn`，不会崩 |
| **没赋值的字段不会出现** | 后端 `WsMessage` 上有 `@JsonInclude(NON_NULL)`。做增量合并时不要把"字段缺失"当成"值变成 null"，那会把座位状态清空 |
| **推送只当"该刷新了"的信号** | 数据库才是事实来源。消息乱序或丢失都不该让界面显示错数据 |

### 3.4 这里的 `console` 与小程序端策略不同

`utils/websocket.js` 里有若干 `console.warn` / `console.error`（非 JSON 消息、缺少 type、
未定义的消息类型、连接错误）。这是**有意保留**的：Web 端的诊断信息在浏览器控制台里，
不影响用户。

但**小程序端不一样** —— 那边全项目只允许 `utils/ws.js` 的 `debugLog()` 一个出口，
交付版还是关着的。两端的口径不要互相照搬。

## 4. Vite 代理与监听地址的坑

### 4.1 `host: '127.0.0.1'` 这条修复丢过一次

Windows 上 Vite 默认**只监听 IPv6 的 `[::1]:3000`**，表现为
`localhost:3000` 能开、但 `127.0.0.1:3000` 打不开（浏览器和工具默认走哪个不一定）。

`vite.config.js` 的 `server` 里已经显式绑了 IPv4 回环：

```js
server: {
  port: 3000,
  host: '127.0.0.1',
  // ...
}
```

**这条修复在重新落的副本里丢过一次，注意别再丢。**

### 4.2 `/ws` 代理必须开 `ws: true`

```js
proxy: {
  '/api': { target: BACKEND, changeOrigin: true },
  '/ws':  { target: BACKEND, changeOrigin: true, ws: true }
}
```

少写 `ws: true` 就完不成协议升级，表现是 REST 全通、页面数据正常，**但实时刷新一直连不上**。

### 4.3 `BACKEND` 是给本机用的，与内网穿透无关

`vite.config.js` 里的 `const BACKEND = 'http://localhost:8080'` 是给 **Vite dev server
代理到本机后端**用的，**不需要**跟着内网穿透域名改。

想让别人从外网打开管理端，得**另开一条穿透隧道指向 3000**，与小程序那条互相独立。
（小程序那条隧道指向 8080，只改 `utils/config.js` 的 `baseUrl`。）

## 5. 环境与运行

| 项 | 说明 |
| --- | --- |
| **必须先 `npm install`** | `node_modules` 被 `.gitignore` 忽略，重新拉的副本里没有。忘了这步 `npm run dev` 会直接报找不到 `vite` |
| 端口 | 管理端 3000，后端 8080（`/api` 与 `/ws` 都代理过去） |

## 6. 改 UI 时的注意事项

1. **颜色与状态文案只改 `constants/status.js`**，不要在各 `.vue` 里写死；
2. **已删除的页面不要加回来**：黑名单、拖拽布局、复杂个人中心、动态系统设置、报表导出
   （方案 §41）；
3. **离线角标是叠加层**，不要让它覆盖业务状态颜色；
4. **`stores/seat.js` 是全馆座位状态的唯一持有者**，
   快照来自 `GET /api/admin/seats`、增量来自 WebSocket。别在页面里另存一份座位数组，
   否则两处状态会不一致；
5. 图表用 ECharts 5，大屏上的数字指标口径与后端 `/api/admin/dashboard` 保持一致，
   不要在前端二次聚合。

## 7. 交付前自检

| 检查项 | 期望 |
| --- | --- |
| 依赖完整 | `npm install` 后 `npm run dev` 能起，`npm run build` 能出 `dist/` |
| 无平台 SDK | `package.json` 里没有 `mqtt` / `crypto-js` / 任何 IoT 平台 SDK |
| 无密钥 | `.env.*` 里只有地址；全仓库 grep `api-key`、`secret`、`product-id` 无命中 |
| 网络出口收敛 | 所有请求都走 `utils/request.js`；WebSocket 只有 `utils/websocket.js` 一个实例 |
| 错误提示可读 | 后端连不上时显示「请确认 library-seat 已启动」，而不是 axios 原文 |
| 401 提示正确 | 密码打错显示「用户名或密码错误」，登录过期显示「登录已过期，请重新登录」 |
| 状态口径 | 颜色与小程序端一致；`4` 是闪烁 |
| 默认口令 | `Admin@123` 公网部署前必须改（在后端的种子 SQL 里） |
