## 1. 这个工程是什么

一个微信小程序，是本系统里**学生侧的唯一入口**。

它只做四件事：

- 看座位图、预约座位；
- 看我的预约、取消未签到的预约；
- 签到后做**暂离 / 回座 / 离座**三个动作；
- 维护自己的昵称、查看只读的校园卡号（头像统一为默认图片，不做上传）。

它明确**不做**的事：不读传感器原始值、不推导座位状态、不做预约状态机、
不直连物联网平台、不保存任何业务数据。一句话 —— **小程序只负责展示、点击和把结果画出来**。

### 1.1 它在整条链路里的位置

```
FSR402 压力 + HC-SR505 人体红外
        ↓
STM32F103C8T6
        ↓ UART
ESP8266-01S
        ↓ MQTT
OneNET（物模型 + 设备身份）
        ↓ HTTP 推送
Spring Boot（全部业务逻辑）
        ↓
MySQL
        ↓ WebSocket（同一份 /ws/seats 广播）
   ↙              ↘
Vue3 Web 管理端     微信小程序（REST 取数 + WebSocket 增量刷新）
```

OneNET 只承担「设备 → 后端」这一段，**小程序从头到尾不接触 OneNET**，
拿到的座位状态、预约、用户资料、校园卡绑定全部来自自建后端。

### 1.2 四端分工

| 端 | 做 | 不做 |
| --- | --- | --- |
| STM32 | 采集压力/红外、双传感器融合、报警、OLED、RFID 读取、串口 | 数据库、预约、用户、WebSocket |
| ESP8266 | Wi-Fi、MQTT、断线重连、数据转发 | 业务状态机 |
| OneNET | 设备接入、物模型、消息转发、属性与服务下发 | 预约规则、用户管理、学习时长 |
| Spring Boot | 全部业务逻辑：用户、预约、签到、状态机、超时、统计、WebSocket | —— |
| MySQL | 持久化 | 保存大量设备历史 |
| **微信小程序** | **展示、点击操作、发请求、接收推送、刷新页面** | **判断 ADC/PIR、做预约状态机、直连 OneNET** |

├── components/empty/       空状态组件（首页、我的预约页用）
├── utils/                  ★ 只有这 5 个文件
│   ├── config.js           后端地址 + 接口路径 + 业务常量 + 状态枚举

│   ├── ws.js               唯一允许 wx.connectSocket 的文件（实时推送客户端）

> 现在已经拍平成上面这样。`project.config.json` 里**没有** `miniprogramRoot` 了 ——
> 在开发者工具里导入时，目录直接选 `jidian-library/` 这一层。

### 3.1 utils 五个文件各管什么

| 文件 | 职责 | 对外导出 |
| --- | --- | --- |
| `config.js` | 唯一的配置源：`server`（地址/超时/tokenKey/wsPath/重连参数）、`debug.log`、`api`（6 条路径）、`appInfo`、`business`（4 个业务常量）、`seatStatus`（5 项）、`reservationStatus`（6 项） | 配置对象 |
| `request.js` | 唯一的 HTTP 出口。拼 baseUrl、带 `Authorization: Bearer`、翻译错误码、兼容裸数据返回；token 的读写也在这里 | `get/post/put/del`、`baseUrl/isConfigured/getToken/setToken/clearToken` |
| `ws.js` | 唯一的 socket 出口。由 baseUrl 推导 `wss://…/ws/seats?token=`，维持**一条**连接，指数重连，把消息分发给订阅者 | `ensure/close/subscribe/isConnected/socketUrl/MESSAGE_TYPES` |
| `api.js` | 页面唯一的数据来源。接口语义化 + snake_case→驼峰归一化 + 状态文案配色 | 26 个方法，见文件末尾 `module.exports` |
| `util.js` | 日期时间与交互反馈。**只导出页面真正用到的 12 个方法** | `weekdayCN / nowText / toTimestamp / diffMinutes / minutesText / countdownText / clockOf / dayLabel / toast / loading / hideLoading / confirm` |

## 4. 数据流与网络边界

```
页面 ──▶ utils/api.js ──▶ utils/request.js ──HTTPS──▶ Spring Boot ──▶ MySQL
  └──▶ utils/ws.js ────WSS───▶ /ws/seats（收到变化 → 回去调 REST 重拉）
```

三条硬边界：

1. **全工程只有 `utils/request.js` 出现 `wx.request`**；
2. **全工程只有 `utils/ws.js` 出现 `wx.connectSocket`**；
3. 页面不出现任何接口路径与字段名 —— 后端改了字段命名风格，只动 `api.js` 的归一化层，页面一行都不用改。

`utils/api.js` 的归一化同时认 snake_case 与 camelCase，
但那只是**兜底**（防止后端 Jackson 命名策略被改坏时页面整片空白），后端约定仍是 snake_case。

## 6. 状态口径（四端必须完全一致）

### 6.1 座位业务状态 `seat.status`

| 值 | 枚举 | 含义 | 颜色 | 座位格表现 |
| --- | --- | --- | --- | --- |
| 0 | `FREE` | 空闲 | 绿 `#22C08A` | 浅绿底 + 绿边 |
| 1 | `RESERVED` | 已预约 / 等待签到 | 黄 `#F5A623` | 浅黄底 + 黄边 |
| 2 | `USING` | 使用中 | 红 `#F0554B` | 浅红底 + 红边 |
| 3 | `AWAY` | 暂离 | 灰 `#9AA4B8` | 浅灰底 + 灰边 |
| 4 | `ALARM` | 异常告警（假占座） | 红闪 `#F0554B` | 同使用中 + 1.1 秒呼吸动画 |

**设备离线不是座位状态**，而是独立的 `online` 标志，在座位上叠加一个「离线」角标，
**不覆盖**业务状态 —— 一个离线但上次是"使用中"的座位，仍然显示「使用中 + 离线角标」，
不能显示成空闲。

### 6.2 预约状态 `reservation.status`

| 枚举 | 文案 | 标签样式 |
| --- | --- | --- |
| `RESERVED` | 待签到 | `tag-warning` |
| `USING` | 使用中 | `tag-danger` |
| `AWAY` | 暂离 | `tag-grey` |
| `COMPLETED` | 已完成 | `tag-success` |
| `CANCELLED` | 已取消 | `tag-grey` |
| `TIMEOUT` | 已超时 | `tag-danger` |

### 6.3 状态流转

```
正常流程
  FREE ──预约──▶ RESERVED ──RFID签到──▶ USING ──▶ COMPLETED ──▶ FREE
                                          │
                                          ├──暂离──▶ AWAY ──回座──▶ USING
                                          └──离座──▶ COMPLETED

异常流程
  USING ──压力存在 + 红外持续无人──▶ ALARM ──人员回座 / 管理员消警──▶ USING

超时流程
  RESERVED ──15 分钟未签到──▶ TIMEOUT ──▶ FREE
  AWAY     ──30 分钟未回座──▶ COMPLETED ──▶ FREE

取消与强制释放
  RESERVED ──学生取消──▶ CANCELLED ──▶ FREE
  RESERVED / USING / AWAY / ALARM ──管理员强制释放──▶ FREE
```

### 6.4 谁触发状态变化

| 动作 | 触发方 | 小程序端 |
| --- | --- | --- |
| 预约 | 学生（`POST /api/reservations`） | 座位页确认弹窗 |
| 签到 | **RFID 设备**（读卡器 → OneNET → 后端） | 只展示「等待读卡器」，不提供签到按钮 |
| 暂离 / 回座 / 离座 | 学生（`POST .../leave` `/return` `/release`） | 签到页三个按钮 |
| 假占座 | **设备端**双传感器融合 | 只展示告警 |
| 超时释放 | **后端定时任务** | 只展示倒计时 |
| 最终状态 | **一律由后端决定** | 前端不自行推导 |

### 6.5 业务常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| 预约超时 | 15 分钟 | `RESERVED` 未签到 → `TIMEOUT` |
| 暂离超时 | 30 分钟 | `AWAY` 未回座 → `COMPLETED` |
| 设备离线判定 | 120 秒 | 后端按 `last_report_at` 判定 |
| 默认昵称 | 同学 | 注册时昵称是选填项，不填就用它兜底展示 |

前端拿这些值只用于**展示倒计时**，释放动作全部由后端定时任务执行。

## 7. 接口契约

小程序只与自建后端通信，下面是**全部通道**：12 个 REST + 1 个 WebSocket。

### 7.1 通用约定

**返回格式**（编码规范第十二节）

```json
{ "code": 200, "message": "success", "data": { } }
```

| code | 含义 | 小程序端表现 |
| --- | --- | --- |
| 200 | 成功 | 取 `data` |
| 400 | 参数错误 | toast 提示 `message` |
| 401 | 未登录 / token 失效 | 清本地 token，提示重新登录 |
| 403 | 无权限 | toast 提示 |
| 404 | 数据不存在 | 页面显示「记录不存在」 |
| 405 | 接口方法不被支持 | toast 提示 |
| 409 | 业务冲突（如座位已被预约） | toast 提示 `message` |
| 500 | 服务器错误 | toast 提示 |

> 兼容：后端若直接返回裸数据（不带 `code`），小程序也会接受。

**鉴权**：登录后每个请求带 `Authorization: Bearer {token}`，token 存在本地缓存（key = `jidian_token`）。

**字段命名**：后端统一 snake_case（`seat_code` / `reserve_time` / `rfid_uid`）。

**时间格式**：REST 返回 `yyyy-MM-dd HH:mm:ss`；若是 ISO（`2026-09-21T14:20:00`），
`api.js` 会自动把 `T` 换成空格并截到分钟。**WebSocket 的 `timestamp` 是 epoch 秒**，两种格式别混用。

### 7.2 接口总表

| # | 方法 | 路径 | 用途 | 页面 |
| --- | --- | --- | --- | --- |
| 1 | POST | `/api/auth/register` | 学生注册（学号 + 密码 + 选填昵称） | 注册 |
| 2 | POST | `/api/auth/login` | 学生登录（学号 + 密码） | 登录 |
| 3 | GET | `/api/users/me` | 我的资料（含校园卡） | 我的 / 签到 |
| 4 | PUT | `/api/users/me` | 保存昵称 | 我的 |
| 5 | GET | `/api/seats` | 全部座位与状态 | 首页 / 座位 |
| 6 | GET | `/api/reservations/current` | 当前进行中的预约 | 首页 / 我的 |
| 7 | GET | `/api/reservations` | 预约列表（`?status=`） | 我的预约 / 我的 |
| 8 | GET | `/api/reservations/{id}` | 预约详情 | 预约详情 / 签到 |
| 9 | POST | `/api/reservations` | 创建预约 | 座位 |

### 7.3 接口明细

**① `POST /api/auth/register` / `POST /api/auth/login`**

两个接口共用同一套入参 / 出参形状，注册只是多一个**可选**的 `nickname`：

```json
// 注册
{ "student_no": "2021001", "password": "xxxxxx", "nickname": "张三" }
// 登录
{ "student_no": "2021001", "password": "xxxxxx" }
```

响应 `data`（注册与登录**完全一致**，都是 `StudentLoginVO`）：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user_id": 10001,
  "student_no": "2021001",
  "nickname": "张三",
  "avatar_url": null,
  "created_at": "2026-09-30 11:58:00",
  "updated_at": "2026-09-30 11:58:00",
  "rfid_uid": null,
  "rfid_bind_time": null
}
```

后端要做的事：

- **注册**：① 校验学号格式（`^[A-Za-z0-9]{4,32}$`）与密码长度（6~32）；
  ② 查 `student_no` 是否已存在，在就返回「该学号已注册」；
  ③ 密码 **BCrypt 加密**后连同学号写入 `user` 表（并发下靠 `student_no` 的 UNIQUE 索引兜底，
  捕获 `DuplicateKeyException` 后返回同一句提示）；④ 签发 JWT 返回。
- **登录**：① 按学号查 `user`；② 用 BCrypt 比对密码；③ 签发 JWT 返回。

> ⚠️ 登录失败时「学号不存在」与「密码错误」返回**同一句话、同一个错误码**（HTTP 401），
> 这是刻意的 —— 分开提示等于对外提供了一个学号枚举接口。所以别指望从提示里区分是哪种。
>
> 注册成功**也直接返回登录态**（同一个 VO），前端拿到就进首页，不用再补一次登录请求。
>
> `password` 的**校验依据**是库里的 BCrypt 哈希；库里另有一列明文 `password_plain`
> （见 `docs/01-数据库设计.md`，本项目有意的偏离）。但**任何 VO 都不带这两列**，也不进日志。

**② `GET /api/users/me`** — 响应 data（`user` 表 + `rfid_user` 表）：

```json
{
  "user_id": 10001,
  "student_no": "2021001",
  "nickname": null,
  "avatar_url": null,
  "created_at": "2026-09-21 14:20:00",
  "updated_at": "2026-09-21 14:20:00",
  "rfid_uid": "A1B2C3D4",
  "rfid_bind_time": "2026-03-02 14:05:00"
}
```

未绑定校园卡时 `rfid_uid` / `rfid_bind_time` 返回 `null`，界面显示「暂无」。

**③ `PUT /api/users/me`** — 只允许改 `nickname` 与 `avatar_url`，其余字段后端忽略。
「我的」页实际只传 `nickname`：头像固定用 `/images/default_avatar.png`，不做上传。
响应同 ②。`student_no`、`created_at`、`updated_at`、`rfid_uid`、`rfid_bind_time` 一律由后端维护，前端只读。

**④ `GET /api/seats`** — 响应 data 是 SeatVO 数组：

```json
[
  {
    "seat_id": 1,
    "seat_code": "A4-101",
    "area": "科技借阅室",
    "floor": 4,
    "status": 0,
    "alarm": false,
    "online": true
  }
]
```

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `seat_id` | seat.id | 创建预约时用它 |
| `seat_code` | seat.seat_code | 形如 `A4-101`；小程序按 `-` 后的数字解析行列，用于座位图排版 |
| `area` | seat.area | 阅览室名称 |
| `floor` | seat.floor | 楼层数字 |
| `status` | seat.status | 0 空闲 / 1 已预约 / 2 使用中 / 3 暂离 / 4 异常 |
| `alarm` | seat_shadow.alarm_flag | 设备判定的假占座告警 |
| `online` | seat_shadow.online | 设备在线状态，**独立于 status** |

约定：阅览室**不做独立表**，小程序用 `area` + `floor` 归并出阅览室列表；
座位图的行列由 `seat_code` 推导，后端不用返回行列号；
前端**不根据压力值判断有人无人**，只接受设备已融合好的 `alarm`。

**⑤ `GET /api/reservations/current`** — 返回当前 `RESERVED` / `USING` / `AWAY` 的那一单，没有返回 `null`。

**⑥ `GET /api/reservations?status=`**

| status | 含义 |
| --- | --- |
| 不传 / `ALL` | 全部 |
| `RESERVED` | 待签到 |
| `USING` | 使用中 |
| `AWAY` | 暂离 |
| `FINISHED` | 后端归并返回 `COMPLETED` + `CANCELLED` + `TIMEOUT` |

按 `reserve_time` 倒序。没有任何记录时返回空数组 —— 界面显示空态，**不会有任何初始假数据**。

**⑦ `GET /api/reservations/{id}`** — 单个 ReservationVO；不存在返回 404。

**⑧ `POST /api/reservations`** — 请求 `{ "seat_id": 1 }`。按规范 14.3，**只入参 seat_id，没有时段概念**。

后端必须校验：① 座位存在（否则 404）；② 座位是 `FREE`（否则 409「座位已被预约」）；
③ 当前用户没有进行中的预约（否则 409「已有进行中的预约」）；
④ 写 `reservation`（`status=RESERVED`、`reserve_time=now`、`reserve_expire_at=now+15min`）；
⑤ 改 `seat.status=1`；⑥ WebSocket 广播。响应是新建的 ReservationVO。

**⑨～⑫ 三个状态动作**

| 接口 | 允许的流转 | 额外写入 |
| --- | --- | --- |
| `.../cancel` | 只能 `RESERVED → CANCELLED` | `seat.status → 0` |
| `.../leave` | 只能 `USING → AWAY` | `leave_time`、`leave_expire_at = now + 30min` |
| `.../return` | 只能 `AWAY → USING` | `return_time`、清空 `leave_expire_at` |
| `.../release` | 只能 `USING → COMPLETED` | `release_time`、`seat.status → 0`，并生成 `study_record` |

四个都返回**操作后的完整 ReservationVO**，小程序直接用它刷新页面；状态不合法返回 409。

### 7.4 ReservationVO 字段

```json
{
  "id": 2001,
  "seat_id": 1,
  "seat_code": "A4-101",
  "area": "科技借阅室",
  "floor": 4,
  "seat_no": "101",
  "status": "RESERVED",
  "reserve_time": "2026-09-21 14:20:00",
  "sign_time": null,
  "leave_time": null,
  "return_time": null,
  "release_time": null,
  "reserve_expire_at": "2026-09-21 14:35:00",
  "leave_expire_at": null
}
```

> 规范里的 ReservationVO 只定义了 `id / seat_id / seat_code / status` 与五个时间字段。
> `area`、`floor`、`seat_no` 是**建议补充的展示字段** —— 我的预约、签到页、预约详情
> 都要显示「阅览室 + 楼层 + 座位号」。后端不加也能跑（`seat_no` 可从 `seat_code` 推），
> 但 `area` / `floor` 就需要页面再调一次 `/api/seats` 关联，建议直接返回。

### 7.5 `GET /ws/seats`（WebSocket）

REST 负责"进页面时拿一次全量"，座位状态的**变化**由这条 WebSocket 推下来。
地址由 `config.server.baseUrl` 推导（`https → wss`、`http → ws`）再拼 `config.server.wsPath`，
所以换后端地址**永远只改 baseUrl 一处**。

```
wss://api.example.com/ws/seats?token={JWT}
```

- **token 只能放查询参数** —— 小程序的 `wx.connectSocket` 和浏览器的 WebSocket 都不能自定义请求头。
  后端 `TokenHandshakeInterceptor` 在**握手阶段**校验，无效直接 403，
  客户端连 `onOpen` 都收不到（先连上再关会让界面闪一下"已连接"）。
- 角色不限：座位状态本来就由 `GET /api/seats` 对学生开放，推下来的信息不比 REST 更多。
- 微信公众平台要**单独**配一次「socket 合法域名」，它和「request 合法域名」是两个入口。

**后端一共只发三种消息**（字段 snake_case；**没赋值的字段不会出现在 JSON 里**，
`WsMessage` 上的 `@JsonInclude(NON_NULL)` 就是为这个，删掉会把接收端的增量合并逻辑打坏）：

| type | 带的字段 | 什么时候发 |
| --- | --- | --- |
| `SEAT_UPDATE` | `seat_id` `status` `alarm` `online` | 座位业务状态变了（预约、签到、暂离、回座、释放、超时、告警） |
| `DEVICE_STATUS` | `seat_id` `online` | 设备上线 / 被离线巡检判成离线。**不带 status**，免得覆盖业务状态 |
| `ALARM` | `seat_id` `alarm` | 告警标志翻转；业务 `status` 由后端另发一条 `SEAT_UPDATE` |

每条都带 `timestamp`（epoch 秒）。

> **没有 `RESERVATION_UPDATE` 这一种**（规范 §18.4 列了，后端刻意不发）：
> 订单的每一次跃迁必然伴随所在座位的业务状态变化，`SEAT_UPDATE` 的字段是它的严格超集，
> 两种都发只会让客户端对同一个座位合并两次同样的值。
> 页面想实时刷新自己的订单，就按 `seat_id` 对上自己那几单所在的座位。

**三条使用原则**

1. **推送只当"该刷新了"的信号，不当数据源。** 页面收到消息后仍然回去调 REST，
   数据库才是事实来源；消息乱序或丢失都不会让界面显示错数据。
2. **一次只维持一条连接。** 全馆状态是广播给所有人的，多开只是重复消费。
   退出登录必须 `ws.close()` —— 后端按握手那一刻的 token 认人。
3. **后端不发心跳**，所以半开连接检测不到。表现是"页面不再自动刷新"而不是"显示错误数据"：
   `onShow` 和下拉刷新仍会拉全量。

`utils/ws.js` 的另外两个细节：断线重连是**2 秒起步、逐次翻倍、封顶 20 秒**；
连续失败 5 次后暂停（下次进页面 `ensure()` 时清零重试）。

## 8. 跑起来

小程序不吃本地数据，所以**必须先起后端**。

```
1. MySQL 建库    执行 docs/01-数据库设计.md 里的 9 张表 + 种子数据
2. 起后端        默认 8080（VSCode 对 library-seat 按 F5，或 mvn spring-boot:run）
3. 验接口        curl 或浏览器访问 GET /api/seats 有返回
4. 配小程序      utils/config.js 的 server.baseUrl
5. 导入运行      微信开发者工具导入 jidian-library/ 目录
```

### 8.1 第 4 步：配置后端地址

`jidian-library/utils/config.js`：

```js
server: {
  baseUrl: 'https://33307e24.r27.cpolar.top',  // ← 只改这一行
  timeout: 15000,
  tokenKey: 'jidian_token'
}
```

| 场景 | baseUrl |
| --- | --- |
| 开发者工具本机调试 | `http://localhost:8080` |
| 局域网真机 | `http://192.168.x.x:8080` |
| 内网穿透（当前在用） | `https://xxxxxx.r27.cpolar.top` |
| 线上 | `https://api.你的域名.com` |

**留空则小程序不发任何请求**，页面直接提示「尚未配置后端地址」，不显示任何本地假数据。

> cpolar 免费版的随机域名**约 24 小时轮换**，客户端重启就变。
> 地址一变只改上面这一行 —— HTTP 与 WebSocket 都从它推导。
> 但要注意 OneNET 的数据推送 URL 也得同步改，清单见
> [04-小程序开发注意事项](04-小程序开发注意事项.md) §2。

### 8.2 第 5 步：导入小程序

1. 微信开发者工具 → 「导入项目」；
2. **目录选 `jidian-library/` 这一层**（`project.config.json` 就在里面，已无 `miniprogramRoot`）；
3. AppID 填 `wx0384c7d1e1e2d16d`，或点「测试号」；
4. 若用 http / 穿透地址调试：详情 → 本地设置 → 勾选**「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**
   —— 这个开关同时管 `https://` 和 `wss://`，实时推送就不用另外配了。

### 8.3 上线前的域名配置

微信公众平台 → 开发 → 开发管理 → 服务器域名：

- **request 合法域名**：填后端域名（必须 https，且已备案、证书有效）；
- **socket 合法域名**：填**同一个**域名。这是同一个页面上的**另一个输入框** ——
  只配了上面那条的话，REST 全通、页面数据也正常，但**座位不会再自动刷新**；
- 小程序不支持用 IP、不支持自签名证书。

> 实测结论：cpolar 的 `*.cpolar.top` 属于未备案域名，**配不进这两个输入框**。
> 真机联调只能靠"开发调试"绕过校验，且**开发者工具和手机要各开一次**，
> 详见 [04-小程序开发注意事项](04-小程序开发注意事项.md) §3。

## 9. 后端没起时会怎样

| 情况 | 表现 |
| --- | --- |
| 没填 `server.baseUrl` | 座位页 / 首页 / 我的预约 / 我的 显示「尚未配置后端地址」，**不发起任何请求**，不能预约 |
| 填了但服务没起 | 显示网络不可达提示，可点「重试」 |
| 服务起了但没数据 | 首页阅览室为空、我的预约显示空态、座位页显示「后端暂未返回任何座位数据」 |

这是**有意设计**：小程序从不编造任何数据，没有后端就没有数据、也不能预约。

## 10. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面提示「尚未配置后端地址」 | `config.js` 的 `server.baseUrl` 是空的 |
| 提示「网络不可达」 | 后端没起 / 地址写错 / 没勾「不校验合法域名」 |
| 提示「登录已失效，请重新登录」 | token 过期，或后端重启导致签发的 token 失效；重新登录即可 |
| 登录一直失败，后端日志有 `40164` | 微信后台 **IP 白名单**没加后端机器的出口公网 IP，见 04 文档 §3 |
| 座位页显示「后端暂未返回任何座位数据」 | `seat` 表是空的，先导入座位数据 |
| 阅览室列表是空的 | 座位的 `area` / `floor` 为空，小程序靠这两个字段归并阅览室 |
| 座位图位置错乱 | `seat_code` 需形如 `A4-101`（`-` 后：前几位是行、最后两位是列） |
| 我的预约一直是空 | 数据库里本来就没有预约记录，小程序不显示任何初始假数据 |
| 签到页停在「待签到」 | 读卡器没上报 `rfid_scan`：查 MFRC522 接线、卡号是否已在管理端绑定 |
| 点座位提示「该座位当前为…」 | 正常拦截：只有空闲且**设备在线**的座位可预约 |
| 「我的」页校园卡号显示「暂无」 | `rfid_user` 表里还没有绑定记录，由管理员在 Web 端绑定 |
| 座位数据对，但不会自动刷新 | socket 没连上：查 wss 是否可通、token 是否有效；或后端没配 socket 域名 |
