# 01 · 系统总体设计

> 依据：《四端统一最终方案》《实际编码规范_最终版》
> 本文只描述**小程序端**的设计，另外三端（STM32 / Spring Boot / Vue3 Web）由本人独立实现，
> 小程序与它们的边界在本文第 5 节明确列出。

---

## 1. 系统目标

做一个「硬件感知 + 物联网通信 + 云端业务处理 + 微信小程序 + Web 管理后台」的完整本科毕业设计。

小程序端承担的角色是**学生侧的唯一入口**：查座位、预约、看我的预约、签到后操作座位、查学习统计。

核心闭环（小程序所处的环节加粗）：

```
FSR402 压力 + HC-SR501 人体红外
        ↓
STM32F103C8T6
        ↓ UART
ESP8266-01S
        ↓ MQTT
OneNET（物模型 + 设备身份）
        ↓ HTTP 推送
Spring Boot（全部业务逻辑）
        ↓
MySQL
        ↓ WebSocket（同一个 /ws/seats 广播）
   ↙         ↘
Vue3 Web 管理端    **微信小程序（REST 取数 + WebSocket 增量刷新）**
```

## 2. 四个核心亮点

| # | 亮点 | 小程序端的体现 |
| --- | --- | --- |
| 1 | FSR402 + HC-SR501 双传感器融合，减少假占座误判 | 座位页展示设备上报的 `alarm_flag`，异常座位红闪 |
| 2 | STM32 + ESP8266 + MQTT + OneNET 完整物联网链路 | 设备数据由 OneNET 推给后端，小程序只读后端归一化后的 `status` / `alarm` / `online`，不碰 OneNET |
| 3 | RFID 自动签到 | 签到页展示「等待读卡器」状态与本人校园卡号，签到无需手动操作 |
| 4 | Spring Boot + WebSocket 实时同步 | `utils/ws.js` 用 `wx.connectSocket` 连后端 `/ws/seats`，与管理端收同一份广播；页面收到相关座位的变化就静默重拉一次（小程序不能直连 MQTT，但 WebSocket 是支持的） |

## 3. 技术栈（小程序端）

| 类别 | 选型 |
| --- | --- |
| 框架 | 微信小程序原生（WXML / WXSS / JavaScript） |
| 云平台 | 中国移动 OneNET —— **只用于设备接入，小程序不直连** |
| 网络 | `wx.request` 调自建 Spring Boot 的 REST 接口（`utils/request.js`） |
| 数据 | 全部来自后端接口，小程序不保存任何业务数据 |
| 实时 | 待签到期间每 3 秒向后端确认一次状态；其余页面按需拉取 |

明确不使用（规范第 49 条删除清单）：FreeRTOS、Redis、EMQX、Kafka、RabbitMQ、OTA、
RBAC、多管理员、设备分组、Excel/PDF 导出、用户画像、复杂热力图、积分与信用分、
黑名单等级、复杂消息中心、指数退避、`pending_display` 持久队列、`pir_hold_time` 云端配置、
多套物联网平台、复杂历史设备缓存。

## 4. 状态机（四端必须完全一致）

### 4.1 座位业务状态 `seat.status`

| 值 | 枚举 | 含义 | 前端颜色 |
| --- | --- | --- | --- |
| 0 | `FREE` | 空闲 | 绿 `#22C08A` |
| 1 | `RESERVED` | 已预约 / 等待签到 | 黄 `#F5A623` |
| 2 | `USING` | 使用中 | 红 `#F0554B` |
| 3 | `AWAY` | 暂离 | 灰 `#9AA4B8` |
| 4 | `ALARM` | 异常告警（假占座） | 红闪 `#F0554B` |

**设备离线不是座位状态**，而是独立的 `online` 标志，在座位上叠加「离线」角标，不覆盖业务状态。

### 4.2 预约状态 `reservation.status`

`RESERVED` / `USING` / `AWAY` / `COMPLETED` / `CANCELLED` / `TIMEOUT`

### 4.3 状态流转

```
正常流程
  FREE ──预约──▶ RESERVED ──RFID签到──▶ USING ──▶ COMPLETED ──▶ FREE
                                          │
                                          ├──暂离──▶ AWAY ──回座──▶ USING
                                          └──离座──▶ COMPLETED

异常流程
  USING ──压力存在 + 红外持续无人──▶ ALARM ──人员回座 / 管理员消警──▶ USING

超时流程
  RESERVED ──15 分钟未签到──▶ TIMEOUT ──▶ FREE
  AWAY     ──30 分钟未回座──▶ COMPLETED ──▶ FREE

取消与强制释放
  RESERVED ──学生取消──▶ CANCELLED ──▶ FREE
  RESERVED / USING / AWAY / ALARM ──管理员强制释放──▶ FREE
```

### 4.4 谁触发状态变化

| 动作 | 触发方 | 小程序端 |
| --- | --- | --- |
| 预约 | 学生（小程序 `POST /api/reservations`） | 座位页确认弹窗 |
| 签到 | **RFID 设备**（读卡器 → OneNET → 云端） | 只展示，不提供签到按钮 |
| 暂离 / 回座 / 离座 | 学生（小程序） | 签到页三个按钮 |
| 假占座 | **设备端**双传感器融合 | 只展示告警 |
| 超时释放 | **云端定时任务** | 只展示倒计时 |
| 最终状态 | **一律由云端决定** | 前端不自行推导 |

## 5. 四端职责边界（小程序只做第 5 条）

| 端 | 做 | 不做 |
| --- | --- | --- |
| STM32 | 采集压力/红外、双传感器融合判断、报警、OLED 显示、RFID 读取、串口通信 | 数据库、预约、用户、WebSocket |
| ESP8266 | Wi-Fi、MQTT、断线重连、数据转发 | 业务状态机 |
| OneNET | 设备接入、物模型、消息转发、属性与服务下发 | 预约规则、用户管理、学习时长 |
| Spring Boot | 全部业务逻辑：用户、预约、签到、状态机、超时、统计、WebSocket | —— |
| MySQL | 持久化 | 保存大量设备历史 |
| **微信小程序** | **展示、点击操作、发请求、接收状态、更新页面** | **不判断 ADC / PIR、不做预约状态机、不直连 OneNET 之外的服务** |

> 两条硬规则：
> 1. 前端**不根据 `pressure_adc` / `pir_state` 自己推断「有人无人」**；
>    只有设备上报的 `alarm_flag` 属于设备事实，可以直接映射为「异常」。
> 2. 小程序端所有网络请求只允许出现在 `utils/request.js` 一个文件里，页面统一通过 `utils/api.js` 取数。

## 6. 小程序端目录与数据流

```
miniprogram/
├── app.js / app.json / app.wxss      全局入口 / 页面注册 / 全局样式
├── styles/nav.wxss                   自定义导航栏样式（各页共用）
├── components/empty/                 空状态组件
├── utils/
│   ├── config.js       ★ 后端地址 + 接口路径 + 业务常量 + 状态枚举
│   ├── request.js      ★ 唯一允许联网的文件（HTTP 封装 / token / 错误翻译）
│   ├── api.js          ★ 数据访问层（接口方法 + 字段归一化，页面只依赖它）
│   └── util.js           日期 / 时长 / 倒计时 / 交互反馈
├── images/                           12 个图标（tabBar 3 组 + 页面图标 6 组）
└── pages/                            8 个页面
```

数据流：

```
页面 ──▶ utils/api.js ──▶ utils/request.js ──HTTPS──▶ Spring Boot ──▶ MySQL
```

页面从不直接联网，也不出现任何接口路径与字段名；后端即使改了字段命名风格，
只需要调整 `api.js` 的归一化层，页面代码不用动。接口清单见 docs/04。

## 7. 八个页面的定位

| # | 页面 | 路径 | 定位 |
| --- | --- | --- | --- |
| 1 | 登录 | `pages/login` | 仅微信登录：`wx.login` 换 code → 后端换 openid |
| 2 | 首页 | `pages/index` | 静态总览 + 一个活入口（进入座位图）；「当前预约」卡是动态的 |
| 3 | 座位页 | `pages/seats` | **预约流程起点**：座位图 → 确认弹窗 → 预约成功 |
| 4 | 预约成功 / 详情 | `pages/reserve-success` | 同一页两种形态（`from=detail`） |
| 5 | 我的预约 | `pages/my-reserve` | 5 个筛选 tab + 按日期分组的卡片 |
| 6 | 签到 / 离座 | `pages/signin` | 待签到 / 使用中 / 暂离 / 终态四种状态分支 |
| 7 | 我的 | `pages/mine` | 账号信息 + 校园卡绑定 + 我的预约（编辑资料已融合进来） |
| 8 | 意见反馈 | `pages/feedback` | 静态表单 |
