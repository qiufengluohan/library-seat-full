# 04 · 小程序端接口契约

> **小程序只与自建 Spring Boot 后端通信**，不直连 OneNET、不保存任何业务数据。
> 本文是小程序端与后端之间唯一的接口约定：后端按本文实现，小程序即可直接跑通。
> 代码里的同一份约定写死在 `miniprogram/utils/config.js`（路径）与 `utils/api.js`（字段归一化）。

---

## 1. 数据链路

```
STM32 + ESP8266 ──MQTT──▶ OneNET ──HTTP 推送──▶ Spring Boot ──▶ MySQL
                                                      ▲
                                                      │ HTTPS
                                                 微信小程序
```

- OneNET 只承担「设备 → 后端」这一段；
- 小程序拿到的座位状态、预约、用户资料、校园卡绑定，全部来自后端接口；
- 后端地址未配置时小程序**不发起任何请求**，页面直接给出空态提示。

## 2. 通用约定

### 2.1 返回格式（规范第十二节）

```json
{ "code": 200, "message": "success", "data": { } }
```

| code | 含义 | 小程序端表现 |
| --- | --- | --- |
| 200 | 成功 | 取 `data` |
| 400 | 参数错误 | toast 提示 `message` |
| 401 | 未登录 / token 失效 | 清本地 token，提示重新登录 |
| 403 | 无权限 | toast 提示 |
| 404 | 数据不存在 | 页面显示「记录不存在」 |
| 409 | 业务冲突（如座位已被预约） | toast 提示 `message` |
| 500 | 服务器错误 | toast 提示 |

> 兼容：如果后端直接返回裸数据（不带 `code`），小程序也会接受。

### 2.2 鉴权

登录后所有请求带：

```
Authorization: Bearer {token}
```

### 2.3 字段命名

后端按规范统一用 **snake_case**（`seat_code` / `reserve_time` / `rfid_uid`）。
小程序在 `utils/api.js` 里做了两种写法的兼容（snake_case 与 camelCase 都能解析），
但**建议后端严格用 snake_case**。

时间字段建议返回 `yyyy-MM-dd HH:mm:ss`；如果是 ISO 格式（`2026-09-21T14:20:00`），
小程序会自动把 `T` 换成空格并截到分钟。

## 4. 接口明细

### 4.1 POST /api/auth/wechat-login

微信登录。小程序调用 `wx.login()` 拿到 `code` 后提交，后端用 code 向微信换取 `openid`。

**请求**

```json
{ "code": "081Abc1234567" }
```

**响应 data**

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user_id": 10001,
  "openid": "oXXXXXXXXXXXXXXXX",
  "nickname": null
}
```

**后端要做的事**

1. 拿 `code` 调微信 `jscode2session` 接口换 `openid`（配了 appid/secret 才走真实调用）；
2. 查 `user` 表：`openid` 存在就取，不存在就**新建一条**（`nickname` 留空、
   `created_at` 由数据库默认值写入 —— 这就是「注册时间」）；
3. 签发 JWT，claims 建议放 `userId` 与 `role=STUDENT`；
4. 返回 `token` 与用户信息。

> ⚠️ 微信小程序**拿不到用户的微信号**（官方没有这个接口）。
> 能拿到的唯一用户标识就是 `openid`，因此账号以 `openid` 为准。
> 昵称在表里默认为空，小程序展示为「微信用户」，用户可在「我的」页自行修改。

### 4.2 GET /api/users/me

**响应 data**（`user` 表 + `rfid_user` 表）

```json
{
  "user_id": 10001,
  "openid": "oXXXXXXXXXXXXXXXX",
  "nickname": null,
  "avatar_url": null,
  "created_at": "2026-09-21 14:20:00",
  "updated_at": "2026-09-21 14:20:00",
  "rfid_uid": "A1B2C3D4",
  "rfid_bind_time": "2026-03-02 14:05:00"
}
```

未绑定校园卡时 `rfid_uid` / `rfid_bind_time` 返回 `null`，小程序显示「暂无」。

### 4.3 PUT /api/users/me

只允许改这两个字段，其余字段后端忽略即可。

**请求**

```json
{ "nickname": "张三", "avatar_url": "/files/avatar/xxx.png" }
```

**响应 data**：同 4.2（返回更新后的完整对象）。

> 注意：`openid`、`created_at`、`updated_at`、`rfid_uid`、`rfid_bind_time`
> 都由后端维护，小程序端只读。

### 4.4 GET /api/seats

**响应 data**：全部座位的数组（对应 `SeatVO`）

```json
[
  {
    "seat_id": 1,
    "seat_code": "A4-101",
    "area": "科技借阅室",
    "floor": 4,
    "status": 0,
    "alarm": false,
    "online": true
  }
]
```

**字段说明**

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `seat_id` | seat.id | 创建预约时用它 |
| `seat_code` | seat.seat_code | 形如 `A4-101`；小程序按 `-` 后的数字解析行列用于排版 |
| `area` | seat.area | 阅览室名称 |
| `floor` | seat.floor | 楼层数字 |
| `status` | seat.status | 0 空闲 / 1 已预约 / 2 使用中 / 3 暂离 / 4 异常 |
| `alarm` | seat_shadow.alarm_flag | 设备判定的假占座告警 |
| `online` | seat_shadow.online | 设备在线状态（独立于 status） |

**约定**

- 阅览室**不做独立表**，小程序用 `area` + `floor` 归并出阅览室列表；
- 座位图的排版（行列）由 `seat_code` 推导，后端不需要返回行列号；
- 前端**不根据压力值判断有人无人**，只接受设备已融合好的 `alarm`。

### 4.5 GET /api/reservations/current

返回当前进行中的预约（`RESERVED` / `USING` / `AWAY`），没有则返回 `null`。

**响应 data**：单个 ReservationVO 或 `null`。

### 4.6 GET /api/reservations?status=

| status 取值 | 含义 |
| --- | --- |
| 不传 / `ALL` | 全部 |
| `RESERVED` | 待签到 |
| `USING` | 使用中 |
| `AWAY` | 暂离 |
| `FINISHED` | 归并返回 `COMPLETED` + `CANCELLED` + `TIMEOUT` |

**响应 data**：ReservationVO 数组，按 `reserve_time` 倒序。

> 用户没有任何预约记录时返回空数组 —— 小程序显示空态，不会有任何初始假记录。

### 4.7 GET /api/reservations/{id}

**响应 data**：单个 ReservationVO；不存在返回 404。

### 4.8 POST /api/reservations

**请求**

```json
{ "seat_id": 1 }
```

> 按规范第十四节 14.3：创建预约**只入参 seat_id**，没有时段概念。

**后端必须校验**

1. 座位存在（不存在 → 404）；
2. 座位是 `FREE`（不是 → 409「座位已被预约」）；
3. 当前用户没有进行中的预约（有 → 409「已有进行中的预约」）；
4. 写 `reservation`（`status=RESERVED`、
   `reserve_time=now`、`reserve_expire_at=now+15min`）；
5. 改 `seat.status = 1`；
6. WebSocket 广播。

**响应 data**：新建的 ReservationVO。

### 4.9 POST /api/reservations/{id}/cancel

只能取消 `RESERVED`：`RESERVED → CANCELLED`，同时 `seat.status → 0`。

### 4.10 POST /api/reservations/{id}/leave

只能 `USING → AWAY`，写 `leave_time`、`leave_expire_at = now + 30min`。

### 4.11 POST /api/reservations/{id}/return

只能 `AWAY → USING`，写 `return_time`，清空 `leave_expire_at`。

### 4.12 POST /api/reservations/{id}/release

只能 `USING → COMPLETED`，写 `release_time`，`seat.status → 0`，
并生成 `study_record`（`start_time = sign_time`，`end_time = release_time`）。

> 4.9～4.12 都返回**操作后的完整 ReservationVO**，小程序直接用它刷新页面。
> 状态不合法时返回 409。

### 4.13 GET /ws/seats（WebSocket，规范 §18 / §46）

REST 只负责"进页面时拿一次全量"，座位状态的**变化**由这条 WebSocket 推下来。
地址由 `config.server.baseUrl` 推导（`https→wss`、`http→ws`）再拼 `config.server.wsPath`，
所以换后端地址永远只改 `baseUrl` 一处。

```
wss://api.example.com/ws/seats?token={JWT}
```

- **token 只能放查询参数**：小程序的 `wx.connectSocket` 和浏览器的 WebSocket 都不能自定义请求头。
  后端 `TokenHandshakeInterceptor` 在**握手阶段**校验，无效直接 403，
  客户端连 `onOpen` 都收不到（先连上再关会让界面闪一下"已连接"）。
- 角色不限：座位状态本来就由 `GET /api/seats` 对学生开放，推下来的信息不比 REST 更多。
- 微信公众平台要单独配一次**「socket 合法域名」**，它和「request 合法域名」是两个入口。

**后端一共只发三种消息**（字段 snake_case；**没赋值的字段不会出现在 JSON 里**，
`WsMessage` 上的 `@JsonInclude(NON_NULL)` 就是为这个，删掉会把接收端的增量合并逻辑打坏）：

| type | 带的字段 | 什么时候发 |
| --- | --- | --- |
| `SEAT_UPDATE` | `seat_id` `status` `alarm` `online` | 座位业务状态变了（预约、签到、暂离、回来、释放、超时、告警） |
| `DEVICE_STATUS` | `seat_id` `online` | 设备上线 / 被离线巡检判成离线。**不带 status**，免得覆盖业务状态 |
| `ALARM` | `seat_id` `alarm` | 告警标志翻转。业务 `status` 由后端另发一条 `SEAT_UPDATE` |

每条都带 `timestamp`，单位是** epoch 秒**（REST 里的时间是 `yyyy-MM-dd HH:mm:ss` 字符串，两种格式别混用）。

> **没有 `RESERVATION_UPDATE` 这一种**（规范 §18.4 列了，后端刻意不发）：
> 订单的每一次跃迁必然伴随所在座位的业务状态变化，`SEAT_UPDATE` 的字段是它的严格超集，
> 两种都发只会让客户端对同一个座位合并两次同样的值。
> 所以页面想实时刷新自己的订单，就按 `seat_id` 对上自己那几单所在的座位。

**小程序侧怎么用**（`utils/ws.js` + 各页面）：

| 页面 | 关心的座位 | 收到之后做什么 |
| --- | --- | --- |
| 首页 | `current.seat_id` | 只重拉 `GET /api/reservations/current`，不重绘整页 |
| 座位页 | 当前阅览室里的那些座位 | 400ms 合并一次，再静默 `load(true)` 拉一次全量 |
| 我的预约 | 我还没结束的那几单所在座位 | 400ms 合并一次静默重拉 |
| 签到页 | —— | 它本来就每秒跑倒计时，不额外订阅 |

三条原则：

1. **推送只当"该刷新了"的信号，不当数据源**。页面收到消息后仍然回去调 REST 接口，
   数据库才是事实来源；消息本身乱序或丢失都不会让界面显示错数据。
2. **一次只维持一条连接**。全馆状态是广播给所有人的，多开只是重复消费。
   退出登录必须 `ws.close()` —— 后端按握手那一刻的 token 认人。
3. **后端不发心跳**，所以半开连接检测不到。表现是"页面不再自动刷新"，
   而不是"显示错误数据"：`onShow` 和下拉刷新仍会拉全量。

## 5. ReservationVO 字段

```json
{
  "id": 2001,
  "seat_id": 1,
  "seat_code": "A4-101",
  "area": "科技借阅室",
  "floor": 4,
  "seat_no": "101",
  "status": "RESERVED",
  "reserve_time": "2026-09-21 14:20:00",
  "sign_time": null,
  "leave_time": null,
  "return_time": null,
  "release_time": null,
  "reserve_expire_at": "2026-09-21 14:35:00",
  "leave_expire_at": null
}
```

> 规范里的 ReservationVO 只定义了 `id / seat_id / seat_code / status` 与五个时间字段。
> 这里的 `area`、`floor`、`seat_no` 是**建议补充的展示字段**：
> 我的预约、签到页、预约详情都要显示「阅览室 + 楼层 + 座位号」。
> 如果后端不想加，小程序也能从 `seat_code` 推出 `seat_no`，
> 但 `area` / `floor` 就需要页面再调一次 `/api/seats` 去关联，建议直接返回。

## 9. 网络边界

全工程**只有 `utils/request.js`** 允许出现 `wx.request`；
页面与 `utils/api.js` 都不直接联网。`utils/api.js` 负责把后端字段
归一化成页面结构，页面代码不出现任何接口路径与字段名。

## 10. 后端没起时会怎样

| 情况 | 表现 |
| --- | --- |
| 没填 `server.baseUrl` | 座位页 / 首页 / 我的预约 / 我的 显示「尚未配置后端地址」，**不发起任何请求**，不能预约 |
| 填了但服务没起 | 显示网络不可达提示，可点「重试」 |
| 服务起了但没数据 | 首页阅览室为空、我的预约显示空态、座位页显示「后端暂未返回任何座位数据」 |
