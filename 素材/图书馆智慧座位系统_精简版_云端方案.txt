图书馆智慧座位系统
毕业设计精简版：云端方案

说明：
本方案从原云端方案中精简整理。
目标是保留物联网、OneNET物模型、Spring Boot业务状态机、MySQL数据、RFID签到、异常检测和实时通信等核心内容。
删除Redis、复杂补偿队列、复杂设备管理等非核心功能。

============================================================
一、云端总体架构
============================================================

硬件：

STM32F103C8T6
+
ESP8266
        │
        │ MQTT
        ▼
OneNET Studio
        │
        │ HTTP推送 / OpenAPI
        ▼
Spring Boot
        │
        ▼
MySQL

Spring Boot同时向：

Web管理端
微信小程序

提供REST API和WebSocket。

完整链路：

STM32 + ESP8266
        ↓
OneNET
        ↓
Spring Boot
        ↓
MySQL
        ↓
Web / 微信小程序

核心原则：

1. OneNET负责设备通信。
2. Spring Boot负责业务逻辑和状态机。
3. MySQL负责业务数据。
4. Web和微信小程序不直接连接OneNET。
5. RFID只表示“谁刷卡”，订单决定“哪个座位”。
6. 座位业务状态由Spring Boot统一计算。

============================================================

五、OneNET物模型
============================================================

一、座位设备只读属性

pressure_adc
    FSR402压力值

pir_state
    PIR人体检测

alarm_flag
    告警状态

二、RFID读卡器属性

    最近一次读取的UID

三、座位设备可写属性

seat_display

0 = 空闲
1 = 已预约/待签到
2 = 使用中
3 = 暂离
4 = 告警显示

adc_threshold
    压力阈值

pir_hold_time
    PIR保持时间

四、服务

    强制释放

buzzer_ctrl
    蜂鸣器测试

五、在线状态

设备在线/离线使用OneNET生命周期判断，
不作为普通业务属性处理。

============================================================
六、云端业务状态机
============================================================

基本状态：

空闲
 ↓
已预约/待签到
 ↓
使用中
 ↓
暂离
 ↓
回座
 ↓
使用中
 ↓
离座
 ↓
空闲

超时：

待签到超时 → 空闲
暂离超时 → 空闲

规则：

1. 一个学生同一时间只能有一个进行中订单。
2. 状态只能由Spring Boot修改。
3. 告警不自动关闭订单。
4. 管理员可以消警。
5. 管理员可以强制释放。

============================================================
七、预约流程
============================================================

学生选择座位。

Spring Boot检查：

1. 座位是否可预约。
2. 学生是否存在进行中订单。

检查通过：

创建reservation
状态=待签到
设置签到超时时间

同时：

seat_display=1

然后：

Spring Boot → OneNET → 座位设备

如果OneNET下发失败：

pending_display=1

数据库业务状态仍然有效。

============================================================
八、RFID签到流程
============================================================

1. 学生预约座位。
2. 学生到共享读卡器刷卡。
3. MFRC-522读取UID。
4. STM32上传OneNET。
5. OneNET推送Spring Boot。
6. Spring Boot根据UID查询学生。
7. 查询学生当前订单。
8. 找到订单中的seat_id。
9. 订单变为使用中。
10. seat_display=2。
11. WebSocket通知前端。
12. Web管理端座位变红。

核心：

RFID负责识别人。
订单负责确定座位。

============================================================
九、FSR402 + PIR异常检测
============================================================

基本判断：

压力值超过阈值
+
PIR未检测到人员
+
持续时间超过设定值

触发：

fake_occupy

设备：

蜂鸣器提示
alarm_flag=true
OLED显示告警

Spring Boot：

写入violation
更新座位告警状态
WebSocket推送Web管理端

注意：

异常告警不等于自动释放。

管理员选择：

消除告警

或：

强制释放

============================================================
十、暂离、回座、离座
============================================================

暂离：

使用中 → 暂离

seat_display=3

回座：

暂离 → 使用中

seat_display=2

离座：

使用中 → 完成
完成 → 空闲

seat_display=0

学习时间只计算有效使用时间。

暂离时间不计入有效学习时间。

============================================================
十一、自动超时
============================================================

Spring Boot使用@Scheduled。

每分钟检查：

1. 待签到是否超时。
2. 暂离是否超时。

超时：

订单关闭
座位释放
生成学习记录
seat_display=0

不使用Redis延迟队列。

============================================================
十二、设备上下线
============================================================

OneNET生命周期：

上线：

online=true

离线：

online=false

Spring Boot收到状态变化后：

更新seat_shadow
WebSocket通知Web端

设备离线：

座位增加离线标识。

注意：

设备离线不自动取消学生预约。

============================================================
十三、OneNET消息处理
============================================================

OneNET向Spring Boot推送：

1. 属性上报
2. 事件
3. 上线
4. 离线

处理流程：

收到消息
 ↓

 ↓

 ↓
更新seat_shadow
 ↓
处理业务
 ↓
WebSocket通知

不设计复杂消息队列。

============================================================
十四、数据一致性
============================================================

需要同时修改业务数据和设备显示状态时：

第一步：

MySQL事务修改业务状态。

第二步：

写入seat_shadow.pending_display。

第三步：

事务提交。

第四步：

异步调用OneNET。

成功：

清除pending_display。

失败：

保留pending_display。

定时任务后续重新下发。

这样可以避免：

MySQL已经显示空闲，
设备OLED仍然显示使用中的情况。

本毕设只保留pending_display。

不做：

pending_service
复杂消息队列
多级补偿系统

============================================================
十五、定时任务
============================================================

只保留两个核心任务。

任务1：预约/暂离超时

每分钟检查超时订单。

任务2：设备显示补偿

查询：

pending_display != null

然后重新调用OneNET。

============================================================
二十、管理员强制释放
============================================================

管理员点击：

强制释放

Spring Boot事务：

1. 关闭当前订单。
2. 写入学习记录。
3. 清除告警。
4. 座位状态变为空闲。
5. 写入pending_display=0。

事务提交后：

调用OneNET设置：

seat_display=0

成功：

清除pending_display。

失败：

保留pending_display，等待补偿。

============================================================
二十一、异常处理
============================================================

只处理核心异常：

1. OneNET设备离线
2. OneNET下发失败
3. RFID未绑定
4. RFID重复绑定
5. 预约超时
6. 暂离超时
7. 异常占座

处理原则：

数据库业务状态优先；
设备状态异步同步；
失败后简单补偿。

============================================================
二十二、安全
============================================================

1. OneNET密钥只放Spring Boot。
2. 前端不保存OneNET密钥。
3. 管理员接口使用Token。
4. OneNET推送验证签名。
5. 预约操作使用数据库事务。
6. 一人一单。
7. RFID不能覆盖已有绑定。
8. 管理员重要操作写日志。
9. 条件允许时使用HTTPS。

============================================================
二十六、最终技术原则
============================================================

一句话概括：

OneNET管设备，
Spring Boot管业务，
MySQL管数据，
WebSocket管实时通信。

RFID负责识别人，
订单负责确定座位，
传感器负责发现异常，
状态机负责决定业务状态。

在保证物联网闭环和核心业务完整的前提下，
不引入不必要的生产级复杂组件。
